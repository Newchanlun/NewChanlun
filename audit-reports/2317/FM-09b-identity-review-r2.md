## 新的可复现阻断缺陷：两项均是合法状态误红

### R2-1　工作区有组执行位，但 Git 模式仍是 100644

逐字复现命令：

```sh
python3 -IB "$F/clean_checkout.py"
```

固定提交、完整分离检出、`core.filemode=true`。同一文件，先原样，再从 0644 调到 0654（仅组执行位），再调到 0744（仅属主执行位）。实际输出节选：

```text
对照: status=b'' diff-files=b'' blob==disk=True index=100644 disk=0644
默认: rc=0; GATE11 身份检查 GREEN：提交 106ace51a1，准入材料 49 个文件与钉选相同，语料 110 个文件指纹等于基线
只增加组执行位: status=b'' diff-files=b'' blob==disk=True index=100644 disk=0654
默认: rc=1; RED 工作区文件带可执行位：formal_math/sources/admit/SPEC.md
属主执行位: rc=1; RED 工作区文件带可执行位：formal_math/sources/admit/SPEC.md
属主执行位的 Git 差异： mode change 100644 => 100755 formal_math/sources/admit/SPEC.md
```

`check_admit_identity.py:120–121` 用 `st_mode & 0o111`。在同一可记录模式的 APFS 上，0654 和 0744 对 Git 的意义不同，脚本却不能区分。前者的原始字节相同，索引是 100644，`git diff-files` 和 `git status --porcelain` 都为空；不需要控制 Git 环境或关闭文件模式检查。**属于第二类：内容及 Git 模式均未变的合法工作区被判红。** 按 Git 对普通文件的模式语义判定，保留 0744 必红，补一个 0654 应绿对照。把“任何执行位都禁止”另定为 POSIX 权限策略，会改变“只比较 Git 模式”的合同。

另测：在本机只把 `core.filemode` 设为 false，0644 仍绿；此配置下磁盘变成 0754，Git 状态为空而脚本仍红。该开关本身不会凭空给文件加执行位，也不是 R2-1 的复现条件。未用该实验推断所有文件系统的实际挂载模式。

## 非阻断建议（4 项）

1. **把运行失败与身份不符分开。** `check_admit_identity.py:156–171` 只捕获 `ValueError`。独立对象库缺少 `SPEC.md` 的 blob 时，实际是 Git 返回 128、Python 打出 `subprocess.CalledProcessError` 回溯、进程退 **1**，而非文档承诺的 2。下游已关闭 stdout 时，正常绿输出和 `--print-pin` 都实测退 **120**，报 `BrokenPipeError`。把对象读取和输出（含刷新）失败归到运行错误；这两种都没有把材料放行。
2. **已知路径缺失应报身份不符。** 移走整个工作区 `formal_math/sources/admit` 后，提交仍完整，默认实际退 **2** 并报 `[Errno 2] No such file or directory`。只缺一个叶文件原自测则退 **1**。`:101–104,173–179` 可区分预期路径不存在与无法读盘；前者已有足够证据判不符。两者现在均非零，不计阻断。
3. **自测也用检查器的根路径解码。** 在目录名以换行收尾的真实分离关联工作树，检查器自动定位退 0，自测入口退 1 并有回溯。`selftest_identity.py:146` 仍用 `.decode().strip()`，删掉了路径自身的字节；可复用检查器只剥一个终止符、用文件系统解码的做法。该合法工作树的身份检查本身没有误红。
4. **说准调用边界。** README:18、28、33 中，受信任的 `--root` 是起点；逐级 `lstat` 从它的第一个子分量开始，并不鉴别参数本身是否指向符号链接。README:33 的“只用标准库”指 Python 依赖，系统还必须有 Git；`--root` 是检查器选项，不是自测选项。建议在使用命令旁一次说明。

### 对象、路径和检出行为

```sh
python3 -IB "$F/tree_cases.py"
python3 -IB "$F/worktrees.py"
python3 -IB "$F/attributes.py"
```

- **钉选及提交绑定。** 上轮与本轮的 pin blob 均为 `a6015b03cbb9bb6565aaea52875d2074b5ac1e4f`。代码 `:149–151` 先将 revision 剥离为完整提交号，再用该号读 pin；后续枚举也用同一号。完整号、短号、HEAD、reflog、带注标签及其父表达式实测符合预期；不存在的 ref 和树对象退 2。钉选缺失、是目录或 gitlink 退 2；普通符号链接的目标文字是 blob 内容，不会被跟随，因与清单不符而退 1。这些改 pin 的样本仅用于区分对象类型和所选版本。
- **目录集合。** 两个受检前缀在提交中缺失、是文件、链接或子模块，八个样本均退 1 并明确“不是目录”。更上层祖先被文件替代也退 1。数据内的 gitlink 无论目标提交在不在主仓，都退 1 报 `非普通文件：160000 commit`；没先去读错误类型的内容。准入内含制表和非 UTF-8 字节的额外文件退 1，换行文件名单独报“路径含换行”。
- **前缀边界。** 原生 `ls-tree -r -t -z --full-tree <提交> -- <前缀>/` 会列出从顶层到受检根的真实树节点。准入路径见到三层，语料路径见到四层；`:52–54` 以斜杠为分量边界。新提交有 `admit-x`、`blog2` 以及名含制表与非 UTF-8 字节的前缀兄弟时，门禁仍绿，没有把兄弟收入或把祖先算成子目录。
- **工作树及文件名。** 本机 APFS 大小写不敏感、NFC/NFD 等价；本清单 159 条完整 Git 路径没有一条 NFC 与 NFD 不同。两档 `core.precomposeunicode` 均绿。将一个叶文件实际拼写从 `SPEC.md` 改为 `spec.md`，报告一多一缺，符合按路径清单比较；大小写等价查找并未使这两个叶名字节相等。完整关联工作树的相对根、目录名以换行收尾的自动定位、深度 1 的分离合并检出均绿。最后一例确为两条 parent 记录、可见历史 1 条，不需要下载父对象。
- **属性究竟作用在哪。** 当前受检数据没有 filter、ident、encoding 或 LFS 检出规则。将规则仅写在根属性时，新克隆状态均为空：钉选被检出为 CRLF 或 UTF-16，默认及仅核提交都绿；对数据 `SPEC.md` 指定 CRLF、UTF-16 或可逆 clean/smudge，数据 blob 均未变，但磁盘确实变了，默认退 1、仅核提交退 0。前者的正常 CRLF 配置归 R2-2；后两种要新加属性（自定义 filter 还需要本地驱动），交付给下游的是另一种字节表示，按逐字节合同应拒收，不另算误红。仅设 ident 而内容没有待展开的标记，两种模式均绿。真正把数据迁为 LFS 指针时，磁盘虽可还原原文，**提交 blob 已变**，两种模式都退 1，正确；本次使用本地 LFS 对象，无外部服务。
