## 新的可复现阻断缺陷：1 项

### R5-1 · Git 警告写入断管时，检查器可从 0 变成 2

**第 3 类：文档与行为不符；运行环境边角，不是判定逻辑。** README:14 写「标准错误写不出时诊断丢失，退出码不变。」夹具在私有克隆中建一个分支和一个同名轻量标签，两者都指向精确的受审提交，没有不同材料可供选错。检查器收到同一个可信 `--rev r5-same`；只改变 stderr 有没有读端。

```sh
python3 -IB "$F/probe.py" warning
```

实际输出：

```text
警告可写: rc=0 GREEN=True
warning: refname 'r5-same' is ambiguous.
警告断管: rc=2 GREEN=False
完整提交号、同一断管: rc=0 GREEN=True
直接调用 git / 警告断管: rc=-13
```

直接调用的命令是 `git rev-parse --verify 'r5-same^{commit}'`；`-13` 是父进程观察到的 SIGPIPE。检查器:23–25 让 Git 继承 stderr，:129 要求 Git 成功解析版本。Git 写警告时已终止，:153–158 随后以运行故障退 2；:100–105 的 `note` 只能抑制**检查器自己**写 stderr 的异常。完整提交号在同一条断管上仍放行，排除了材料差异和 GREEN 无法写出的解释。

**处置：只阻断这句文档。** 建议替换为：「检查器自己的 stderr 诊断写不出时，保留原退出码。Git 子进程若因写诊断失败而终止，检查器退 2。」不建议为了兑现旧句而吞掉 Git 的失败，也不把损坏的输出环境归作第 2 类合法环境误红。若只作上述文案修改，核对新句与此对照即可。

## 非阻断建议：2 项

1. 自测的 `ascii-locale-bad-rev` 与三个参数负例仍只核退出码 2（自测:186、189–191）。本次四项的真实原因都对；可让前者再核 `rev-parse`，后三者再核「参数无效」和出错的选项，免得日后因别的运行故障而误算通过。两项断管已经断言 `Broken pipe`，不用改。
2. 如需给人工调用者交代参数边界，最有用的是说明「重复的根或版本取最后一个；空根使用当前目录，不等于省略根参数」。这两种行为都没有跳过材料检查；不用为此拒绝合法的、名字以双横杠开头的目录。

### 两个退 0 的出口，用途不同

`main` 没有“只解析参数就成功”的出口。**普通入口**的 0 只在读同提交 pin、核两棵树、比对清单和指纹、写出 GREEN 后返回（:133–152）。**显式打印入口**有另一个 0：读准入树并写出规范清单，但不比 pin、不查语料（:130–132）。同一私有提交只多一个普通的准入文件、不改门禁文件，实测普通入口 **1/RED**、打印入口 **0/含新路径的清单**。打印成功不能作放行证据。第 1 类未发现仅改材料可使普通检查误绿的情形；第 2 类未发现合法运行环境下对未变材料的误红。
