## 非阻断建议（4 项）

1. **CI 明确绑定仓库、提交与环境。** `check_admit_identity.py:22–27` 继承进程环境，只覆盖替换对象开关与 locale。`GIT_DIR` 能改变 Git 选库；测试中有效目录正常，无效目录退 2。显式传 `--root` 时，磁盘遍历以它为准；另设 `GIT_WORK_TREE` 不等于同时改了磁盘核对根。`GIT_INDEX_FILE` 对不读索引的对象检查没有作用。本次追加正常对象目录、用 `GIT_CONFIG_COUNT/KEY_0/VALUE_0` 传无关配置均仍绿。CI 应用工作流提供的根、提交及受控 Git 配置；不要把作业环境交给被审内容选择。这些环境条件未计作阻断。
2. **已知类型不合格时先报告身份不符。** 同为 `160000 commit` 的 gitlink，目标对象恰在主仓时退 1 并报「非普通文件」，通常的外部目标不在主仓时却退 2：`:38` 先读目标，然后才判类型。两者都拦住了，建议都退 1 并指出条目。另应把工作区读取失败归入有路径的运行错误，保持 README:14 的退出码约定。
3. **写清自动定位与裸仓前提。** 合法的检出目录名以换行收尾时，`:108` 的 `rstrip("\n")` 删掉了目录名自身的字节；实测自动定位退 2、显式 `--root` 退 0。可只去掉 Git 添加的一个终止符，再用文件系统解码。裸仓环境若设置 `safe.bareRepository=explicit`，单传 `--root` 退 2；由调用方合法显式设置 `GIT_DIR`，配 `--root` 和 `--no-worktree` 即绿。无需放宽宿主配置。
4. **把 README:30 的「输入只有一份」限定为引文核对的准入表。** 对身份检查而言，实际输入是两棵树、钉选和语料基线，默认还读工作区。正文归属 PASS、未接总入口这两句可以保留。
