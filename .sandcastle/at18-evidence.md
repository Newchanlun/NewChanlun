# AT-18 的逐票归属与图外重测证据

## 核对逐票产品

新合入用 `at18-product-delivery/1`：票面列出每件产品的合入 SHA 与路径，PR 与 R09 获审 head 的提交消息分别声明同一条「票 → 路径」归属。两份声明必须一致地把路径归给该票；第一父差异中必须有该路径。单独写 `Closes` 不构成产品。

已有合入不回写不可变 head。兼容上界为 R5 开工时的主线 `b9d898dccf46c2a716115eaa1215bc39c458a959`：已获 R09 的旧合入，仍用实际 PR 差异与不可变来源裁定路径。闸前共享合入也须举出逐路径归属；R10 的「票 → 合入」关系不能单独证明路径归属。

## 登记 #1320 十年重测

重测原件归 #1320，按标准外部 manifest 登记；每个 locator 的 SHA-256 都按文件原字节计算。各文件引用同一验收 head。计划的 Git 提交、正式 App 批准和合入均须早于重测开跑。

- 每标的用一份 `at18-heavy-input-series/1` 清单列出 `chunks`（按时间顺序的分块 SHA-256）。每个 `at18-heavy-input-chunk/1` 包含最多 100,000 根原始分钟 OHLCV，分别登记。验收从块的实际时间与行重算首末和总数，要求至少两根且跨满十个 UTC 日历年。标的结果、每次回放与对照中的 `input_sha256` 引这份清单，不引标的名或窗口文字。
- 每标的两次回放分别登记 `at18-heavy-replay-run/1` 运行原件与 `at18-heavy-replay-output/1` 输出原件；运行 ID 不同，各自引用输出 SHA-256，并绑定输入与预注册计划。双跑索引只列这两份运行的 ID 和 SHA-256；验收比较各自产出的交易、声部生命周期及中枢转换。
- 损坏的图外原件仍生成 #1320 诊断；#1279 和 DST-06 只读取图内前因。尚未完成且未正式退役时，重测延期不成为图内必需项。
