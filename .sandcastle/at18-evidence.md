## 证明 #1319 的旧能力由 TB-08 接管

沿用 `feed-wire-inventory/1` 清点五条旧路径。`RETIRED` 要求路径不在最终树 F；每条 `INCORPORATED` 引用 R09 非作者评审差异中的 `feed-wire-disposition/2`，逐旧路径登记替代模块、F 中接入点、TB-08 `check_id` 与承接理由。处分与替代源码在 F 必须保持获审字节。

Rust 用 `rustfmt` 解析 F 的源码，核实现归属、非空实现、公开接入和登记测试对同一导出的调用；封装、重导出及局部别名可用，仅引用或检查签名不算。公开常量核对断言中的值引用。公开接入按 Cargo 特性闭包与登记作业的原生平台核验，平台不明时不放行依赖该平台的路径。执行结果取自已登记作业，本地不执行 Cargo。

Python 驱动按下列门禁核验：

1. **原件和执行。** 从 F 提取受验包、登记测试和 pytest 配置，以 `python3 -I -B` 在隔离环境运行精确选择器。登记用例须全部通过，通过数恰等于 `count`。macOS 使用系统沙盒，Linux 使用支持独立网络命名空间的 `bwrap`；只提供冻结源码、可信运行时及临时目录，不继承凭据或连接场所、账户。隔离不可用、超时或缺少 pytest 等依赖时不得判定收编。
2. **公开与归属。** 仅承认 CPython 原生 `from <module> import *` 的结果；语句失败则整张清单归空，不保留已导入的前缀。模块级函数须同时满足冻结文件的 `__globals__`、`co_filename` 和编译定义集合；绑定方法还要求接收者为由本冻结文件执行类体创建的本地类，或此类的实例（含本地声明的子类实例）。公开本地类仅枚举非下划线开头的本地函数、静态方法和类方法，支持本地装饰器。承接侧须有可执行字节码，排除 `pass`、纯文档字符串及常量折叠的空返回或空生成器（如 `if False: return`、`if False: yield`）。遇到显式 `__wrapped__` 时逐层核归属、排除循环；承接侧还核每层非空及本次确实进入所声明的对象。
3. **精确绑定。** 匹配函数对象或「函数、接收者」对象对，不用共享 `__code__` 代替同一绑定。这区分不同实例的方法、同值或无自由变量的兄弟闭包，以及默认参数不同的兄弟函数。真别名共享同一绑定的公开键；重载后重建公开清单，登记测试与独立探针在各自导入中按公开键对拍。
4. **真实进入与消费。** 从登记测试体实际进入生产公开入口调用的同一承接导出；仅检查 `callable` 或签名不算。未消费的生成器或异步生成器、未等待的协程或后台任务不计覆盖；显式等待 `asyncio.gather`、`wait` 等复合 Future 时按实际完成的等待关系追踪。两侧模块顶层、类体、重载预热和承接侧构造器均不计；合法生产公开入口可调用生产构造器。
5. **独立探针。** 需补证生产接入时，重新导入同一冻结副本，从登记调用及同次内层本地帧提取纯数据，复用具名参数、`**kwargs`，保留 `/` 位置专用与 `*` 关键字专用形状。测试对象和回调（包括容器内部的对象和回调）不得进入探针。
   **有界机械合成契约。** 探针仅用上述纯数据，在有限候选预算内合成常规公开调用：涵盖具名槽、仅位置槽、仅关键字槽、`*args`／`**kwargs`、已核验的本地元类与 `__new__`／`__init__` 双钩子；按源位置索引扣除已用实参，试有限的默认／覆盖组合，按 `inspect.Signature.bind` 的 `repr` 或 CPython 原生绑定的字面诊断逐键删键。任意 Python 适配器的可达实参一般不可判定；超出该契约的公开形态须由门 4 的登记测试直接经生产公开入口调用同一承接导出取证，不扩张门 5 的合成启发式。门 5 不为外来元类、外来 `__new__`／`__init__` 合成实参，也不接收测试对象或回调（含容器内）；未实际进入公开承接、未消费的生成器及未等待的协程均不计覆盖。

**承接语义由 R09 判断。** 对通过上述门禁的冻结本地非空函数，由 `feed-wire-disposition/2` 的承接理由与 R09 非作者代码审查对照获审源码，核定其是否真正承接原能力。一般程序的逻辑充分性不能机械判定：未声明 `__wrapped__` 的自定义转发、跨模块原地修改的归因、运行期开关早退及过滤谓词是否充分，均属该语义审查。和 Rust 一样，运行期驱动不以污点启发式或结果快照推断这类业务等价性。

## 登记 #1320 的十年分钟数据与两次重放

`at18-heavy-preregistration/2` 计划必须在开跑前完成 Git 提交、正式 App 批准和合入。它附上每标的冻结窗口、完整性总 bar 数、按序的分块首末／计数／数据 SHA-256，以及 UTC 交易周日历和带理由的已批缺口。沿用旧窗口时，首末日期及总量必须与冻结原表一致；BRN、DX 原表不足十年，只有另行冻结并审批的十年快照才能重测。替换快照须在获审计划中写明来源及原因。

- 每标的用 `at18-heavy-input-series/1` 按顺序登记实际分块原件 SHA-256；每个 `at18-heavy-input-chunk/1` 最多 100,000 根分钟 OHLCV。连续同值分钟可无损地以 `runs` 中的起点及分钟数登记，不能用首末时间推定区间内的数据。每块的冻结摘要取 JCS 编码的 `{symbol, interval, rows}`（普通 bar 的 `minutes=1`；不含事后才能得知的 F）；实际分块还必须由其外部 manifest 按原字节登记。
- 按分段交易周重建应有分钟区间，扣除获批的假日、休市或缺失窗，与实际块逐项对账：首末须跨满十个 UTC 日历年，块序、区间、每块摘要及总数必须完全一致。周末和正常维护不算缺失；多日异常缺口必须预先列入获批表。标的结果、回放与对照均用 `input_sha256` 绑定实际分块索引。
- 两次重放分别登记 `at18-heavy-replay-run/1` 与 `at18-heavy-replay-output/1`，独立的运行 ID 与输出原件才能比较交易、声部生命周期和中枢转换。
- 尚未完成且未正式废弃时，#1320 保持 OPEN，重测列为 `required=false`；提前关闭使报告 FAIL。损坏的图外原件仍生成 #1320 诊断，#1279 和 DST-06 继续读取图内前因。

合法废弃只能由同一决策票的 OWNER 在后续 `at18-heavy-retirement-change/1` fence 中撤销或替代。记录须绑定 `decision_ticket`、`ticket: 1320`、`obligation: ISSUE_1320_HEAVY_MEASUREMENT`、原 `decision_sha256` 与 `approval_comment_id`；`disposition` 为 `REVOKE` 或 `REPLACE`，后者还须登记不同的 `replacement_sha256`。普通评论不改变授权。
