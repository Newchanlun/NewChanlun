本目录只做清点：把登记册「清单 D」里的判例逐个回原文核对，写成一张机读表，并标明每条回归需要什么数据、仓内有没有。**没有取任何行情数据，没有写数字化脚本，没有跑 `lake` 或 `lean`。**

- `cases.jsonl`：61 条判例，28 个 `group`，100 条 cite。
- `check.py`：对 `cases.jsonl` 的机械核对，`python3 -I fm60a-inventory/check.py`（只用标准库；准入表从 git 对象 `7d0082ff6f8b1d7d9b7b98eb24712723d0a95d9c` 读，取不到退 2）。
- 引文括号约定：`【归属 课号:行号】「…」` 缠师逐字；`『…』` 网友或编者；`〈…〉` 概括。本文里引原文处照此。

## 做了什么

1. 读 #2324 票面与开工评论；读登记册（`evidence/2310-fm09-register-r3`）第五节 D-1 表（31 行）与 D-2，**只当待办线索**。
2. D-1 每个引文（58 处）回语料原行逐字核对：全部是原行的逐字子串，**引文字句本身没有错**；出入都在日期、归属区、点位清单与归纳语上（见下）。
3. 每条判例的 cite 从原行逐字截取，`char_span` 由 `str.find` 定位并要求片段在行内唯一；`check.py` 再逐字核对。
4. 每条 cite 对准入表现算：整段落在某一条记录的某一个 `author_spans` 内才是 `硬证据`，否则 `二级，未提升`；网友、编者的话标 `speaker` 非作者，tier 为 `非作者，不作证据`。

- 没有把任何判例提升为「已验证」；`硬证据` 只表示**引文字符在准入表的作者区间内**，不表示断言成立。

- 没有评论或修改任何 issue，没有开 PR。

### 关于「二级，未提升」

准入表只覆盖台账摘过的那些句子，不是整行。所以正文区里一行的某个字符落在准入表之外，不等于它不是作者的话，只是**没有准入记录**。例：014:30 一行里准入表只有 `235–323`、`323–405` 两段，前面「用5周与10周均线构成的买卖系统」那句在正文区但未入表，记二级。该行内还嵌有「（注：7月5日）」一类编者括注，不在任何 cite 内。

### 关于 `zone`：解盘与课间

语料里没有任何字面标记区分「解盘」与「课间」；登记册说「都是缠师本人贴在课后的博文」，台账的分法也不随标题或发帖时间走（例如同课同日风格的帖，105:146 记课间、105:178 记解盘）。我只在两种情况下给明确的区：

- 界标 `↑正文` 之前：`正文`（界标行号写在 `zone_basis`，`check.py` 机检）；
- 帖头字面含「每日解盘」：`解盘`（2 条：048:66、050:48）；
- 作者对网友提问的回复（帖头 + 网友引文 + 作者答复的结构明确）：`答疑`。

其余课后博文一律写 `拿不准`，`zone_candidates` 列候选、`register_zone` 记登记册标的区，不替登记册选。`zone` 不影响 tier（tier 只由准入表决定）。
