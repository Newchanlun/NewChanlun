# FM-60a 原典作者陈述库机读格式说明（`fm60a-author-statements-v1`）

> **交付物定位（R3 改定，经陈述库 R1 独审定点修正）**：本目录的正式内核交付物是**纯作者陈述库**——每条记录只保存缠师在原文里说过的具体命题及其完整语境、语气、条件限定、对象指代、依存关系与说话人确认依据，力求**不回读博文也能准确读懂、不会读错**。
>
> **本交付物不是什么**：本交付物**不包含任何整理者建模（`organizer_models`）、合成数值实例（`instances`）、额外补入前提（`added_premises`）或预期输出**。怎样把这些陈述落成可计算条件、补哪些前提、用什么数去测试，留给后续编写形式化定义与回归测试的作者，在他们自己的名下、带着他们自己列出的前提去做。

## 二、`kernel-cases.jsonl` 字段契约（`fm60a-author-statements-v1`）

每条判例仅含**元信息**、**逐字引文（`cites`）**与**作者陈述（`author_statements`）**三部分，`check.py` 机械禁止出现 `organizer_models`、`instances`、`added_premises`、`synthetic_witnesses`、`structure_spec`、`assertions`、`counterfactuals` 等任何建模/实例字段。

### 1. 顶层元信息
- `schema_version`：固定 `"fm60a-author-statements-v1"`
- `case_id`、`group`、`category`（`kernel_only` / `both`）、`exemplar`（`true`）、`target_concepts`、`evidence_grade`（按全条 `author_statements[*].refs` 现算）、`base_and_pen`（准确写明各引文实际准入等级、字符切片与笔期，不把正文二级冒充硬证据）、`paired_cases`、`real_market_dependency`。

### 2. 逐字引文锚点（`cites[]`）
每条含：`cite_index`, `lesson`, `line`, `speaker`, **`speaker_basis`**, `quote`, `char_span`, `zone`, `in_admit_table`, `admit_id`, `tier`, `from_inventory`。
- **原清点表作者引文 100% 保留**（`from_inventory=true`）；
- **`speaker_basis`（必填非空）**：尤其对未命中 `7d0082ff` 准入表 `author_spans` 的二级材料，逐条写明确认该段确系缠师本人说话而非网友原话或行内编者注的依据（帖头与发文时间、`↑正文` 真实行号界标、连续问答编排、`==` 答疑分隔符、无行内编注与外层引语），供非作者人审直接核查。

### 3. 作者陈述（`author_statements[]`）
每条陈述对应原文中作者说的一件事，包含以下必填字段：

| 字段 | 契约说明 |
|---|---|
| `statement_id` | 判例内唯一编号（`AS1`, `AS2`, ...） |
| `context` | 说话场景对象：`scene_kind`（8 值枚举：`事后复盘` / `当日更正复盘` / `当日盘后分析` / `一般规则与举例` / `图例分析` / `课后答疑` / `布置作业` / `后续规则调整`）、`post_timestamp`（区分本篇主帖时间、插入另帖帖头与具体答复时间；若正本仅能定到日期而未载答复时分秒，如实写「仅知日期/确切答复时分秒原文未载」，严禁把下一条问答的署名时间倒配给上一条）、`time_anchor`（区分文中说到的行情日期、相对时间锚点及跨期词——例如「以后」指自提出之时起的一段适用期而非单一交易日；不得把原文未载的市场起日写进逐字时间锚）、`summary`（该句实际所处上下文；若复用前文括注如 `054:54`，须写明实际发话位置与本例复用对象）。 |
| `mood` + `mood_note` | 7 值封闭枚举（`直陈事实` / `条件句` / `假设或反事实` / `预测` / `事后回顾` / `设问或留作作业` / `引述他人`）加非空 `mood_note`。**区分「怎么说（语气）」与「对什么说（范围）」**：复盘旧日行情标 `事后回顾`，真含条件命题标 `条件句`，自设反问/作业标 `设问或留作作业`；**不要为了回避 `直陈事实` 而把对象量化范围（「除了最后一个」）、尺度观察许可（「都可以看成」）、图例特定分解下的判断或无条件操作指示（「一定要用同一种软件」）强改作 `条件句` 并捏造触发前件**——七值枚举无独立许可/指示类时，可录作 `直陈事实` 并在 `mood_note` 与 `scope_qualifiers` 写明其许可、范围或指示性质。 |
| `antecedent` | 当 `mood` 为 `条件句` 或 `假设或反事实` 时必填非空字符串，其他语气必须为 `null`。**前件只能来自原文且只收作用于整句的条件**：互斥分支的条件随各自结论保留（如 `011.AS5`），不得强行合并为总前件；一段内已有无条件当日定性、后接两条「如果」后果分支时（示范：`043.AS4` 拆出 `AS6`/`AS7`），当日定性单列且 `antecedent=null`，两条分支各自单列并依存于定性句；**严禁把操作指示（「就在……回补」）或整理者自造范围搬入前件**。 |
| `scope_qualifiers` | 原样保留的尺度、范围、许可、指示与外层限定语列表（如「除了最后一个」「都可以看成」「可以当下地等待」「在1分钟级别显微镜下」「另外，请注意」「觉得以后可以把笔的成立条件略微放松一下」），严禁改写为「是」「都是」「已经」。 |
| `statement` | 逐词可对回 `refs` 的忠实转写；若原文有相对时间锚点，在对应词后以 `（YYYY-MM-DD）` 保留所指日期（该日期须登记在 `context.time_anchor` 中；若是「以后」等起始期表达，写明「自（YYYY-MM-DD）晚起以后」以防窄化为单日）；除此类时间锚点日期外，**不得出现任何不在 `refs` 里的数值**，也不得私自添加引文未出现的限定词（`严格`、`唯一`、`必然`、`已`）。 |
| `objects_and_values[]` | 逐项登记陈述中的已知字面数值（`kind="literal_number"`）与关键对象（`kind="symbolic_object"`），并**分层区分「作者所指对象」「所问精确字段」与「哪一范围确实未明说」**：对已明确的图级、时段、段号、分解对比组、参照轴（如 0 轴）与已知局部形态须直接登记为已知对象，不留空数组让读者误以为无对象；**仅对同课/同例原文确未给出的部分**（如具体报价、区间端点对应哪一顶点、未展开的完整细部或算法）填写精确字符串 `"原文未指明"` 及 `unspecified_note`——若同例后文已有作者明说（如 `054:54` 对 `d7g7` 形态、`057:30,40` 对 89/78 局部结构），须拆开已知形态与未知报价，**不得在 `unspecified_note` 承认后文有答案却仍把该结构标为 `"原文未指明"`**。 |
| `depends_on_statements[]` | 本条成立所依赖的同判例其他陈述列表（每项 `{statement_id, relation, note}`，`relation` 取 `语境前提` / `分解前提` / `指代前文` / `图设条件` / `规则例外配对` / `规则依据`），构成**有向无环图（DAG）**。 |
| `qualified_by_statements[]` | 指向同判例中对本条加以限定、补充例外、合读对照或方法约束的陈述编号（例如 `011.AS4→AS6` 跌回中枢后的超短线一买再介入、`012.AS4→AS7` 10:40 未成枢答疑、`012.AS5→AS6` MACD 局限、`021.AS5→AS8/AS9` 89/78 已知局部结构、`026.AS4→AS12` d7g7 已知形态、`026.AS9→AS10` 升级例外、`027.AS5→AS7` 与 `028.AS7→AS11` 两种分解在 g7 处的合读对照、`027.AS5→AS6` 末段 d7g7 形态依据、`031.AS1/AS2→AS5` 同软件复核限定、`043.AS2→AS3/AS4` 与 `043.AS4→AS6/AS7`）。 |
| `evidence_tier` | 仅按本条自身 `refs` 现场重算的准入等级（本批 72 条中：纯 `硬证据` 31 条、纯 `二级，未提升` 40 条、`混合（含硬证据与二级）` 1 条即 `020.AS2`，因同句前段设问引出 `01段` 属二级而答语属 `ADMIT 917` 硬证据）。 |
| `effective_tier_with_dependencies` | 按本条 `refs` **并上全部传递 `depends_on_statements` 的 `refs`** 现场重算的有效等级。注意该字段只合并传递 `depends_on_statements`，**不自动合并 `qualified_by_statements`**；因此下游读完整解释时须同时沿 `depends_on_statements` 与 `qualified_by_statements` 读全。 |
| `refs[]` | 指向 `cites[]` 的非空逐字切片。 |

## 三、下游（FM-60b / 定义作者）如何使用本库

1. **按等级取句 vs 按等级取完整解释是两种读法**：读取任意陈述时，须同时沿 `depends_on_statements` 与 `qualified_by_statements` 读全语境、分解前提、方法限定（如 `031.AS1/AS2→AS5` 同软件要求）与作者明说的例外/合读（如 `011.AS4→AS6`、`026.AS9→AS10`、`027.AS5→AS7`、`028.AS7→AS11`）。若某筛选口径放不下必需的二级例外、方法限定或分解语境，应将整组标为不适于该筛选，**绝不可裁掉例外或限定后照发规则**。
2. **尊重「原文未指明」标签（并区分标签计数、制作者核对与独立审阅范围）**：本批 9 例共有 **40 项**对象的 `precise_point_or_field == "原文未指明"`（40 为当前标签计数，制作者已逐项人工核对并剔除同例他处已明说的结构，但计数本身不等同于 40 项均已由独立第三方逐项证明未知，具体审阅范围见各轮独审报告）。定义作者若要构造具体测试数据，须在自己的测试代码里显式声明补入的前提，并把测试失败如实归因为「在该前提下与作者陈述不相容」，不得当作作者字面报错。
3. **有效等级分布（72 条陈述现算口径）**：
   - **单条自身等级**：`硬证据` **31 条**、`二级，未提升` **40 条**、`混合（含硬证据与二级）` **1 条**（`020.AS2`）；
   - **含传递依存有效等级（`effective_tier_with_dependencies`）**：有效 `硬证据` **12 条**、有效 `混合（含硬证据与二级）` **42 条**、有效 `二级，未提升` **18 条**（其中单条硬 31 条拆为有效硬 12 / 有效混合 19；单条混合 1 条为有效混合 1；单条二级 40 条拆为有效二级 18 / 有效混合 22）。需要提升二级语境/规则时请走 #2336 / #2337，不越权提级。
4. **草稿文件不作真值**：`draft-models-unreviewed.jsonl` 仅作灵感或对照参考，不得直接导入回归测试，且不得脱离警告文件孤立分发。

## 四、`check.py` 机检范围与证明不了的事

- **`check.py` 机械检查的**：`classification.jsonl` 61 条双射、隔离文件对齐、禁止建模/实例字段、逐字引文切片与准入表 `7d0082ff` 现场重算、`↑正文` 界标、原清点表作者引文保留、`speaker_basis` 非空、拒绝已标非作者的 cite 入 `refs`、语气 7 值枚举、`条件句`/`假设或反事实` 必带 `antecedent`、核对陈述/前件中可抽取的阿拉伯数字与数值对象在 `refs` 中是否数值匹配（含中文数词数值映射与容差比对，仅放行已在 `time_anchor` 登记的 `（YYYY-MM-DD）`；「逐字」检验仅针对引文切片）、高风险未引限定词拦截、`原文未指明` 必带说明、`depends_on_statements` 指向存在且无环、`qualified_by_statements` 指向合法、`evidence_tier` / `effective_tier_with_dependencies` / `evidence_grade` 现场重算一致。
- **`check.py` 证明不了、必须靠非作者人审的**（详见 `LIMITATIONS.md` §一）：
  1. **二级文本的实际说话人与 `speaker_basis` 内容准确性**：未命中准入表 `author_spans` 时，机检只查 `speaker=="作者"` 且 `speaker_basis` 非空，**既不能证明**该切片不是网友原话、转述他人或行内编者注，**也不能校验 `speaker_basis` 文字里写的界标行号或答复时间戳是否准确**；
  2. **转写忠实性与前件归属**：机检无法判断是否删掉了外层条件或同句例外、前件是否真是原文条件（而非整理者自造前件或对象集合）、是否把「可以看成/可以等待」改写成已发生事实；
  3. **语气判定与适用时间**：机检无法判断 `mood` 是否判准、相对时间锚点日期解析是否正确、跨期词（如 `081:110` 的「以后」）是否被窄化为单日或误套用到前一日；
  4. **跨句指代、依存与限定边是否漏连或错连**：机检只查已写出的 `depends_on_statements` 合法无环与 `qualified_by_statements` 存在，无法发现漏连的分解前提、漏配的作者例外/合读/方法限定或指代错位；
  5. **对象覆盖完整度、修饰对应与「原文未指明」核准**：机检只验已列对象的字段结构，**不能证明 `objects_and_values` 已覆盖该句全部已知对象**（空数组也会通过）、**不能证明某数值在 `refs` 中出现就一定修饰了正确对象**，也无法判断标成 `"原文未指明"` 的项目是否已在同例他处明说。
