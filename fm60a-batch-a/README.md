# FM-60a 原典判例数字化：甲批（#2324 第二步）

只用不需注册、不需令牌的公开接口，覆盖调查报告 5.1 的 A 档。**只做字面核对**：原文给的日期和价位，在数据里是不是那样。没有算分型、笔、线段、中枢、背驰、买卖点，也没有评价任何断言；没有碰 `lake`、`lean`，没有注册或付费。

引文括号约定同清点表：`【归属 课号:行号】「…」` 缠师逐字，`『…』` 网友或编者，`〈…〉` 概括。

## 做了什么

| 产物 | 内容 |
|---|---|
| `fetch.py` | 取数，写仓外原始目录与 `raw-manifest.json`（入库的是清单，不是原始数据） |
| `build.py` | 从原始数据聚合周、月线，切窗口，做两来源比对，写 `windows/`、`compare/`、`cases-digitized.jsonl` |
| `check.py` | 标准库，`python3 -I fm60a-batch-a/check.py` |
| `windows/` | 21 个窗口文件。个股每条判例两份：`<case>.csv` 不复权、`<case>.qfq.csv` 前复权 |
| `compare/` | 两来源逐项比对：`summary.json`、`index-daily-diffs.csv`、`index-daily-dateset-diffs.csv`、`stock-daily-diffs.csv`、`agg-vs-native.csv` |
| `cases-digitized.jsonl` | 14 条判例，一行一条 |

## 没做什么与原因

- **601628 的 5 分钟线（009、010）**：BaoStock 没有 2007 年数据，按约定不换来源硬凑，标 `需补数据`。
- **拿不准是否属于 A 档，不做**：
  - FM60A-040：要日线加 30 分钟，30 分钟不在 A 档。
  - FM60A-061：工行、北辰实业、水井坊的代码与日期要先回原文补齐，且含分钟线。FM60A-060 清点表已标不可回归。
  - 个股判例里要分钟线的，如 007、008（权证）。
- **不在本批**：上证指数分钟线、权证、依赖图片的判例，以及清点表标「不可回归」的 044、058、060。
- 没有开 PR，没有评论或修改任何 issue。

## 复权口径的结论

**本批个股判例的引文都没有给价位，只有日期**（001 至 006、009、010）。所以「原文价位与哪一份对得上」无从判定：两份都留，结论是 `都无法对照`，不是「都对不上」。已有线索但没有进引文：014:36 作者说「后面由于除权，价位上似乎比这个要低了」，014:50 的编者括注称作者看的是不复权图（编者注，非作者原话，不作证据）。014:196 另有「5月26日的37元多」一类价位，不在本批 cites 内，没有核。

两个事实要带着走：

1. 前复权数值不稳定：BaoStock 用涨跌幅复权法，新浪的前复权数值与之不同，且前复权随取数时点变化。例如 600519 在 2003-06-27 的收盘，BaoStock 不复权 24.97、BaoStock 前复权 3.6410、新浪前复权 3.14。
2. 原文如果后来补价位，应先问清作者看的是哪一种，再选窗口文件。

## 已知局限

- 窗口时间标记：日线是交易日日期；周、月线是区间内最后一个交易日（标记的是 K 线结束），另列起始日。周线按 ISO 周（周一至周日）归组，月线按自然月，节假日跨周的周线由实际有成交的日子聚合。
- 指数收盘点位在 2007 年当时如何取，没有核实（调查报告第 4 节）；本批只记录数据里的值。
- 本批没有一条价位核对是点位敏感到 0.08 点（那是 FM60A-031，不在 A 档）。
- 许可：各接口的许可条款没有逐一核对；仓内只放了每条判例用到的窗口（小样本）与摘要，原始数据没有入库。

## 复现

```bash
# 在带 baostock、yfinance、akshare 的环境里（原始数据落仓外）
python fm60a-batch-a/fetch.py --raw-dir <仓外目录>
python3 -I fm60a-batch-a/build.py --raw-dir <仓外目录>
python3 -I fm60a-batch-a/check.py   # 退出码 0 全过，1 有不符，2 环境问题
```

重跑 `fetch.py` 会换取数时刻，前复权数值与新浪的返回也可能随时间变化；`build.py` 在原始文件 sha256 与清单不符时拒绝运行。
