## 字段约定

键序固定：`eid, labels, kind, object, direction, claim, finding, cites, ids, locator, history, status, origin_status, related, closed_at, residual, evidence`。

- `eid` 稳定、不复用。返修删去的 E081、E082 留空号；新增行从 E083 起。
- `object`：这一行说的是哪种对象。`doc_line` 指被审文档某版本的一句话（主册、手册、附录）；`record` 指冻结台账、帖头明细、人工理由等数据记录，冻结件按原样留存不等于现行错误，`claim` 写明是否冻结；`tool` 指护栏或核验脚本。审阅者对将来做法的告诫、对裁决草案的测试不入表，见「非实物事项」。
- `direction`：`defect` 是审阅者指出的缺陷；`confirmed_fix` 是审阅者核实过的已订正差分。后者的 `claim` 写订正后的内容（初版原句确有的才写进来），`status` 一律 `closed`。
- `claim` 写当初有问题的命题，不是现在的正确写法。`closed` 只表示该命题在原处已撤或已改，不表示恢复了被撤销的说法。
- `status = recurred`：原处已改对，同一问题在别处被定位。这时 `origin_status` 写原处的状态（本表均为 `closed`），`related` 指向别处那一行，别处那一行另记自己的状态并互相指回。其余行 `origin_status` 为空串。`partial` 只用于同一处局部改对。
- `related` 也用于不改状态的关联（如 E014↔E015）。
- `status = not_applicable` 只用于三审护栏 G1–G3 与旧核验脚本的缺陷，原因写在 `residual`；它只表示草案给护栏限定的未来角色，不表示 V3 护栏已通过或已修复。
- `ids` 是台账 id（不是物理行号）。
- `locator` 形如 `V3:M:384`、`V2:Jold:310`、`V3:H:369-378`；缺录写 `V3:L:!cite=018:26`。文件简称：M 主册，H 手册，附录1、附录2，L `tmp/ledger_final.jsonl`，J `tmp/pool_375_recheck_r3.jsonl`，Jold `tmp/pool_375_recheck.jsonl`，EX `tmp/hard_cite_exclusions.json`，G `guards/guard_register.py`，GM `guards/g3_manual.json`，GR `guards/README.md`，VF、VR `tmp/verify_final.py`、`tmp/verify_report.py`，RM `fm09-register/README.md`。缺陷所在的旧版本位置与 V3 现状位置并列给出。
- `history[].report_lines` 是报告副本的物理行号；`status_then` 中 `relocated` 表示该轮把问题定位到别处。
