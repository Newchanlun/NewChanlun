## 字段约定

- 键序固定：`eid, labels, kind, claim, finding, cites, locator, history, status, closed_at, residual, evidence`。
- `claim` 写当初有问题的命题，不是现在的正确写法。`closed` 只表示那条命题在原处已撤或已改，不表示恢复了被撤销的说法。
- `history[].report_lines` 是报告副本的物理行号，用分号分隔多个行或区间。
- `status = not_applicable` 只用于三审护栏 G1–G3 与旧核验脚本的缺陷，原因写在 `residual`。同一 A4 中的现行出处记录错误是数据错误，不是护栏缺陷，仍记 `still_wrong`。
- `closed_at` 写“被审提交短哈希，第 N 轮确认”。

## 生成与自检

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -I fm09-admit/errata/tools/build_errata.py
PYTHONDONTWRITEBYTECODE=1 python3 -I fm09-admit/errata/tools/check_errata.py
```

源数据在 `tools/errata_src.py`；`build_errata.py` 按顺序分配 `eid` 写出 `errata.jsonl`。`check_errata.py` 检查 JSON 合法、键齐全且有序、`eid` 连续、取值合法、`closed` 有 `closed_at`、`partial`/`recurred`/`not_applicable` 有 `residual`、报告行号不越界；再从报告副本抽编号（一至三审按正则抽，两次裁决独审按脚本里列出的“指向实物的发现”逐行核字样），与表内 `labels` 及下方排除块对账，未覆盖即退出 1。
