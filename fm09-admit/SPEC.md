## 总体

台账里 `who == "正文"` 的全部条目，共 790 条，一条不多一条不少，按台账原序。

## 要判断的事

对每一条：台账的 `quote` 在原行里占哪些字符；这些字符里哪些确实是缠中说禅本人在这篇课文里自己说的话。

不算作者文字的：
- 编者或整理者插入的注，无论有没有「注」字头，无论括号形式。典型：行尾括注、「娇注」、以第三人称称呼作者的括注。
- 作者转引的他人原话：作者引用网友、古人、他人文章的原句。引号之外作者自己的评述算作者文字。
- 读者或网友的发言被排进了正文区。
- 标题、日期、署名、图注等非正文成分。

每条必须打开原行，并读它前后各至少三行的上下文再判。不许只看台账的 `quote` 与 `note` 字段下结论；`note` 字段只是线索，可能是错的。

## 输出

一个 JSON Lines 文件，每行一条，键按下列顺序，全部必填：

| 键 | 类型 | 含义 |
|---|---|---|
| `id` | 整数 | 台账 id |
| `lesson` | 字符串 | 三位课号 |
| `line` | 整数 | 原行的行号，从 1 起 |
| `quote_spans` | 数组的数组 | 台账摘句在原行里的字符区间，左闭右开，按 Unicode 字符计，从 0 起。摘句带省略号分成几段的，每段一个区间，按原次序。在原行找不到的写空数组 |
| `author_spans` | 数组的数组 | `quote_spans` 之内确属作者文字的区间。完全干净时与 `quote_spans` 相同。整条不可用时为空数组 |
| `verdict` | 字符串 | `clean`（全部是作者文字）、`trimmed`（去掉非作者部分后仍有可用的作者文字）、`reject`（不可用） |
| `nonauthor_kind` | 字符串 | `none`、`editor_note`、`quoted_other`、`reader`、`non_body`、`not_found` 之一。有多种时取占字符最多的一种 |
| `reason` | 字符串 | `clean` 时可以只写「干净」。其余必须写明非作者部分是什么、凭原行或上下文里的哪个可见记号判断的 |
| `author_text_sha256` | 字符串 | 把 `author_spans` 各段文字按次序直接拼接后的 UTF-8 字节的 sha256；空时写空字符串 |

文件末尾不附汇总。另写一个同目录的 `README` 说明：实际处理条数，三种判定各多少条，拿不准的条目 id 清单及原因，所用脚本的路径。

## 自检（交卷前必须通过）

- 恰 790 行，id 集合等于台账里 `who == "正文"` 的 id 集合，次序相同。
- 每个区间都在原行长度之内，`author_spans` 的每一段都落在某个 `quote_spans` 之内，各段不相交且递增。
- `verdict` 与 `author_spans` 一致：`clean` 时二者相等；`reject` 时为空；`trimmed` 时非空且严格小于 `quote_spans`。
- `author_text_sha256` 可由原行与 `author_spans` 重算得出。
- 两个已知实例必须答对：id 1259（081:42）的行尾括注不是作者文字，判定不能是 `clean`；id 265（020:56）注之前的摘句是干净的。
