# ADR 0065：原会话端点同址换代

> 正本：本文件是 `production_session` 在正常关停或崩溃后重新提供原会话本地 Unix socket 的正本。
> 最后裁定：[#2079](https://github.com/Newchanlun/NewChanlun/issues/2079)（2026-11-20，P 类，依 #1909 代理独审裁定，非 `UserSigned`）。

## 裁定

**每个受管域每代新建一个监听器，公开绝对路径不变。** [ADR 0039 裁定三](0039-production-entry-inventory-and-unique-launcher.md#三唯一正式-launcher-的-seam) 的 `production_session` 仍是正式 launcher。部署监督器独立于 launcher，持有会话作业的启动排他权，负责回收证明。它在专用非特权 OS 身份下启动受信发布助手。发布助手核对指令，执行名字操作，通过受信通道把本代 FD 交给 launcher；launcher 只交给指定域进程。发布助手不是第二个会话入口，不装配业务进程。域进程有本域监听权，无目录写权；发布助手和 launcher 都不新增域写权或发送权。

既有部署入口在具名、版本化的会话部署记录 `production-session-deployment/1` 中选择 `endpoint_mode`，不写回原会话 manifest。默认 `direct`，无该记录也按原合同直绑；显式指定 `managed-rotation` 才适用本文。改选须创建新的获准部署版本，不能运行中切换。受管模式限同一宿主上的进程接续，并要求该部署具备本文规定的独立监督、名字保护及内核监听核验。

部署保留原客户端连接权限和原会话协议、请求身份、资源限制。换代空窗内，残留路径没有监听时客户端可遇 `ECONNREFUSED`，退役后尚未 bind 时可遇 `ENOENT`；旧连接也会断开。这些是传输暂不可用，不能据此认定业务未提交。新代不继承旧监听 FD、待受理连接或已受理连接；客户端按原协议查询同一身份，或在原协议允许时重投同一请求。X 的已有调用与责任不因断线消失，不自动补发。

**未选入保持原合同。** 原 manifest、直接 pathname bind、独立 `serve` 和 wire 调用不增加登记、目录、FD 或恢复回执前提。直接路径占用依旧拒绝。受管条件不成立即拒绝受管接续，不改地址、不以空库冒充原库、不退回直绑或旧 writer。

## 各域接续与 launcher 监督

正常关停保留名字；到新实例发布前才判断能否退役。按下表从原配置枚举受管监听名。按宿主目录项比较规则对同一和其他已登记会话的**有效登记**判重；一个目录项只能有一个有效登记代。已废止的登记仅供追溯，不占有效登记，也不授予处置权。

| 域与公开地址 | 整会话正常关停后 | 整会话崩溃后 |
| --- | --- | --- |
| S：launcher manifest 的 `s.socket` | 核 S 正常关库和回收证明，发布助手原址换监听器，只向新 S 交付。仍核 R4 与原会话身份。 | 监督器证明已回收后才换监听器。按 S 正式崩溃恢复处理原接纳身份；R4 或持久身份失败则拒绝。 |
| E：经济 manifest 的 `e.socket` | 核 E 的正常关库和回收证明，只向新 E 交付原址新监听器。 | 按 E 正式恢复合同核 Recorded/Pending、责任和持久写者代，不能恢复成旧 Open。 |
| 各 Bᵢ：`economic.b[i].chong` 匹配经济 manifest 的 `chongs[j].chong_id`，取 `chongs[j].socket` | 逐重核正常关库和回收证明，只向对应重的新 B 交付原址新监听器。 | 各 B 重放原归属应用，核本域代与原协议所需的 E 来源身份；不能用场所净仓重建原账。 |
| X：所选 profile 实际声明并监听的本地端点 | 若 X 自己明确报告正常完成，并证实已回收，发布助手只向新 X 交付原址新监听器。没有 X 自身正常结果的按异常列处理；S/E/B 的关库记录不能代填。 | 监督器还须证实旧 X 发送子进程退出；有本地监听才换 FD。X 依原合同核持久发送身份、排他锁、`MayHaveCalled` 与在途责任，不能因接通 socket 获准发送。 |

[#2077](https://github.com/Newchanlun/NewChanlun/pull/2077) 的有序关库合同仅覆盖 S/E/B。X 没有本地监听器时，不登记地址、不传 FD、不增 Ready RPC；仍核获准 profile 的启动条件、持锁和持久身份。X 的对外连接地址不属于受管端点。取证基线上，[历史模拟 X](https://github.com/Newchanlun/NewChanlun/blob/5a1ac9de73766f0a943c156f97cb467b7d690218/rust/src/history_simulation/runtime.rs#L866-L897) 监听 `history_simulation.socket`；[非该分支的 X 骨架](https://github.com/Newchanlun/NewChanlun/blob/5a1ac9de73766f0a943c156f97cb467b7d690218/rust/src/bin/x_execution_session.rs#L201-L234) 不监听 profile 的 `endpoint`。

**launcher 仍活着，单域退出。** 选入后，launcher 监督循环将退出域标为不可用，清除全会话 Ready，不回收其它健康域、不修改该域的名字、不自动重拉该域。健康域继续处理不依赖故障域的合法工作；依赖故障域的操作仍按已有协议失败，不绕过。未选入的 S/E/B 任一退出即回收会话、X 退出只记录的行为不变。单域接续及单域 E/B 当前回执与 E 来源代的接线归 #1411；本 ADR 只验隔离，不把它当作单域恢复成功。[#2082](https://github.com/Newchanlun/NewChanlun/pull/2082) 的全 E/B 恢复计划不能在健康域上代验，不能为取其回执迫使它停机或交锁。

**launcher 崩溃。** 现任部署监督器在允许新 launcher 启动和写入前，须持有会话作业排他并封堵前代复起，出具覆盖旧 launcher、发布助手、各域、持 FD 后代和 X 发送子进程的回收证明。证明绑定原部署和宿主身份、boot ID、原会话作业及其成员，并证明相应作业已终止、进程回收、无受控 FD 副本或越界转移。任一孤儿仍存活、暂停或证明不全，拒绝启动和名字变更，保留现场；不为清名杀进程。只有旧作业确已回收时，新 launcher 才按上表崩溃列继续。即使作业已回收，也不因此授予旧目录项处置权。管道 EOF（包括 launcher 崩溃）、PID 消失或探活失败不构成回收证明。正常停机则另需各域的正常结果，不能把强杀当作正常关库。

**宿主重启。** 独立部署记录只接受受信 OS 取得、绑定同一获准宿主的旧新 boot ID；确认新旧不同且无跨宿主或越界 FD 传递时，可作为旧宿主进程与 FD 已回收的证据，按异常接续。只有时钟变化、无法绑定原宿主或缺旧 boot ID，不能这样取证。换 boot 不证明原目录或登记仍连续；原址不存在或锚变化时走下一节的重新登记。

## 名字处置权与重新登记

1. **首次登记。** 部署监督器保有持久的部署记录，绑定部署版本、宿主及 boot ID、不可变会话配置、域/重 ID、原绝对路径、锚、发布身份、登记代和会话作业。发布助手在受保护的持久状态目录保存按域日志，记录发布/退役意图、端点代、成功 bind 的目录项身份和完成状态。两份记录与互斥状态都放在 S 测量和业务库之外，不存于会随 socket 目录消失的临时文件系统。初次登记须确认原址为空；不能把直绑遗留或不明对象补登记为受管资产。
2. **排他。** 从核验到名字变更及状态提交，发布助手须持有该目录项的排他资格。部署持续禁止域、客户端、旧入口及同发布身份的其他作业绕开互斥。绝对路径从根到最终条目不得经符号链接、`.` 或 `..`；锚及可改变解析结果的祖先、挂载和权限须受保护。用无法改写锚的域身份与专用发布身份分离目录写权；同 UID 可绕过时，`0700`、协作锁、PID 或 inode 都无效。锚、挂载或发布身份变化即失去旧登记的名字操作资格。
3. **先记意图，再改名字。** 只有前代回收、排他、保护连续性和完整登记同时成立，且原位置确为登记的同代 socket，才允许发布助手 unlink 该目录项。先持久记录绑定旧对象的退役意图，退役后记完成；确认空址后另持久记录新端点代的发布意图，再原址 bind。只有已记 `已发布` 及具体目录项身份才交 FD。设备号、inode、类型和属主用于查错，不是处置权来源；目录项 inode 也不是监听 FD 的 inode。
4. **中断按证据续接。** 有退役意图时，只有旧对象和退出证据仍匹配、排他连续才续做；若原址已空且上述退役意图和排他连续仍可证，补记退役完成。仅有发布意图、现场为空且可证本次作业及 FD 回收时，结束该次尝试，以新端点代重试。bind 后已有对象、却未写完 `已发布` 时，报「端点需恢复」并保留原对象：发布意图没有成功 bind 的身份凭据，排他不能补这条绑定；退役意图则已引用完整登记的旧对象。完整登记对应的对象消失、发布日志丢失、对象被替换或保护失效也报「端点需恢复」，不猜测、不自动移动或删除。
5. **「端点需恢复」的出口。** 由部署监督器封堵旧登记代的作业和发布资格，核对独立部署记录或其可信恢复原件，证明前代回收。发布助手在本次获准部署的排他范围内重验原址、当前锚与保护。部署监督器先持久记录旧代封堵和本次重登许可。确认原址为空后，发布助手依该许可在同一笔登记提交中记旧代废止及其凭据、开启新登记代。登记提交后方可按空址首次发布；重试同一许可只续做该次重登，不再开一代。临时目录因同宿主换 boot 而消失时，先由已获授权的部署动作备好原路径的受保护锚；不可借旧登记动现场。只有发布日志丢失、仍能用独立部署记录定位前代时，才可这样重登。连原会话的部署/登记绑定或封堵也无法恢复，继续拒绝。原址上若仍有对象，另由具备独立授权的运维处置；本 ADR 不准发布助手认领或移除它。等原址确认空、其他前提也成立后，才执行上述作废与重登。
6. **FD 定向交付和内核核验。** 发布助手与 launcher、launcher 与域的交付均使用定向继承白名单或已认证的私有通道；部署、域、登记代、端点代与同次 FD 一起绑定在该私有启动交付，不由公开请求提供。接收者核来源、域、代、`AF_UNIX`、`SOCK_STREAM`，并核 `getsockname` 的绝对地址字节等于预检通过的原 manifest 地址。**接收者必须直接向内核查 `SO_ACCEPTCONN` 且结果为真。** 不支持该核验的平台不属于受管模式支持范围，选入即拒绝；对具体 FD 查询报错或返回 0 均拒绝，不改走其他证明。错传、多传或拒绝时关闭相应副本，正常交付后上游释放多余副本；兄弟域、客户端以及后续 exec 不得获取 FD。域按原协议服务，不再按名字 bind 或 unlink。

## 先做布局核验，再接业务恢复

[ADR 0059 裁定第 1–4、6–10 条](0059-production-session-layout-contract.md#裁定) 继续管路径解析、布局、前置拒绝和禁用放行开关。直绑 S 的第 6 条例外依赖 S 打开 driver 后才 bind；受管模式不能借用。正式入口在改名字、传 FD、建域文件或拉起写域前，只读核验受管地址、登记、角色和布局。受管 S、E、各 B、适用 X 及登记、发布、互斥写足迹避开测量域 M：`P` 目录本身、`P` 内 S 族条目及其子树、`A` 及其子树。检查目录项所在和实际目标目录，不扩大到 `P` 的其余子树。命中即 `InvalidDomain`，点名字段和地址，不做变更。既有 `state_dir` 例外不用于存放受管发布状态。接 FD 仅换传输装配；各域原有的资源、媒体、持久身份、锁与 R4 核验照常运行。

**端点代不等于会话代或持久写者代。** 整会话从原 manifest 字节及其引用的域配置确定静态会话、库和身份。若本域持久写者代仍等于 manifest 代，沿用该代，不要求额外恢复回执。若需要推进或已不等于 manifest 代，只从该域对原配置、库、域、前代与当前代核过的正式恢复凭证取值。若恢复已提交却丢回包，用同一恢复身份取回原件并核其仍授权当前代。不能改原 manifest 的 epoch、读整数手加一、借历史回执或端点代赋予写权；`serve` 持本域锁后仍须核当前持久代。

#2082 候选 `329be34f5a9ca9c2bcc38ae75783304cc654904c` 的 `--economic-recovery-plan` 示范整会话 E/B 的显式当前回执装配；B 分别得本域与 E 来源代。#1411 负责接齐各域凭证（含 S/X）、处理原代与恢复后代混合的整会话，并核同一会话的 E 来源身份；不以全 E/B 计划强行给无需换代的域升代。故障隔离、各证据类恢复和外效保留继续按 [SPEC #1340 C09.3、C09.7–9](https://github.com/Newchanlun/NewChanlun/blob/efc1ddc4d6c015f4f8c6d44f904d704a88308b46/.chanlun/review-results/issue1339-r2-spec-20260909/view/spec/SPEC.md#L326-L332) 与 [ADR 0038 的 #1539 修订](0038-dual-run-determinism-recovery-seek-asknown.md#修订1539恢复语义按证据类分述2026-11-02) 执行。

端点存在或可连都不是 Ready。S 以新域进程实际答复原协议具名读请求；E 和各 B 核自身锁、持久身份并实际提供原协议服务；X 按所选 profile 的实际服务或持锁状态核验。未过启动门的域不处理业务写入。逐域报就绪或首错，只在原合同要求的域均已就绪时报告全会话 Ready；总状态不能卡住健康域。

## 候选取舍与实证

- **同址新建监听器。** [Linux 探针第 1–3、6–9 行](https://github.com/Newchanlun/NewChanlun/blob/5a1ac9de73766f0a943c156f97cb467b7d690218/.chanlun/review-results/issue2079-endpoint-rotation/linux-fresh.log#L1-L9) 记录不同 worker 在原址答复 `from-1`、`from-2`。同 worker UID 的客户端不能在锚目录内新建条目，也不能改名或删除该 socket。第 4–5 行记录待受理且已写入的旧连接随第一代最后一个监听 FD 关闭收到 `ECONNRESET`；第二代只受理夹具的新连接。该方案需要证明排他和 FD 回收，有短暂断连，不能自动接管陌生对象。
- **跨代保留监听 FD。** [Darwin 第 1–4 行](https://github.com/Newchanlun/NewChanlun/blob/5a1ac9de73766f0a943c156f97cb467b7d690218/.chanlun/review-results/issue2079-endpoint-rotation/darwin-fd.jsonl#L1-L4) 与 [Linux 第 1–4 行](https://github.com/Newchanlun/NewChanlun/blob/5a1ac9de73766f0a943c156f97cb467b7d690218/.chanlun/review-results/issue2079-endpoint-rotation/linux-fd.jsonl#L1-L4) 记录地址与 inode 未换、二代处理空窗排队的旧请求、最后持有者关闭后路径仍在。末次另 bind 的 `EADDRINUSE` 是[探针断言](https://github.com/Newchanlun/NewChanlun/blob/5a1ac9de73766f0a943c156f97cb467b7d690218/.chanlun/review-results/issue2079-endpoint-rotation/probe.py#L74-L80)，不是日志 errno 字段。该候选不满足旧队列隔离，不是本合同的可切换项。
- **直绑或改址。** 直绑用于未选入部署。轮换私有路径、使用抽象名或单独重建运行目录不能证明原路径被原客户端复用；只比 PID、inode 再按名删除没有排他保障，已由 [#1823 复核](https://github.com/Newchanlun/NewChanlun/issues/1823#issuecomment-6994092216) 否决。

同址新建只在 OrbStack 的隔离 Linux 容器夹具实跑，发布者为容器 UID 0、无 capabilities，未记录内核版本。Darwin 完全未跑同址新建，只跑了保留 FD 对照。探针未运行产品 writer、正式协议、业务恢复或真实部署。受管实现声称支持的环境须逐个跑下列验收；Darwin 对照不能授予支持名分。

## #1411 的实施验收

精确实现头用正式入口在无真实外效的受管环境验收。Linux 入口测试落 `rust/tests/production_session_entry.rs`；持有不同 OS 身份、宿主启动和故障注入的用例放同一正式入口的受控作业。保留原配置、构建、平台/内核、实际进程组与 PID、域回执、退出证据和响应。表中是实施门。

| 验收 | 二值判据 |
| --- | --- |
| `managed_endpoint_orderly_restart` | L1 从登记空址启动，input-1 得到 `Committed`，记完整原回执及库身份；S/E/B 正常关库、X 按自身证据分类。L2 以原 manifest 字节、原库、原绝对路径、原会话接续，未换代且持久代等于 manifest 时不提供额外回执，其余域出示当前恢复凭证。经正式读口固定 cut-1，回执与首次响应逐字节相同；input-2 得到 `Committed` 且读回持久提交；同身份重投不重复业务效果。 |
| `managed_endpoint_crash_isolation` | launcher 活着时，分别让 S、E、一个 B、适用 X 真实退出。结果是退出域不可用、全会话不 Ready、该域没有新进程及名字变更；见证健康域不依赖故障域的正式新提交。不得为局部故障停或重拉其它域；单域重拉及 E/B 局部回执不计此项。 |
| `managed_endpoint_launcher_crash` | 强杀 launcher。有存活孤儿或回收证明缺失时，新启动拒绝、各端点和登记字节保持、未开始域恢复或 spawn。监督器按原权责回收旧作业并取得退出证据后，新启动凭完整证明按异常列接续各域、原址提供原服务。两个分支均不得把旧 launcher 的崩溃记为全会话正常关停。覆盖已持久接纳但丢回包，用原身份取原恢复回执不重复升代，保留 `MayHaveCalled` 责任；simulation 与受控场所夹具按 ADR 0038 分别验证。旧直绑的 #1823 OBS 对照保留实际首错。 |
| `managed_endpoint_ownership_and_interruption` | 在每个声称支持的环境，以真实发布身份和另一真实域身份运行正式入口。按 [#1823 SAFE](https://github.com/Newchanlun/NewChanlun/issues/1823#issuecomment-6550850441) 验活实例、暂停、PID 复用、错域/错属主、不明或替换对象、链接、祖先或保护失效均不改原对象；同步点内域身份不能改变名字，第二发布作业不能进入。错域或额外 FD、非监听 FD、内核核验失败均拒绝，无降级，旧积压不进新 handler。中断退役可凭原意图续接；发布完成缺失且现场有对象只报「端点需恢复」。 |
| `managed_endpoint_recovery_exit` | 在隔离夹具中分别触发 bind 后未记完成、已发布地址因同宿主重启被清空、发布日志丢失。已有对象时默认原位保留，并用单独获准的夹具处置使原址为空。保留独立部署记录并核前代回收；重启子例核同宿主新旧 boot ID。重核锚和排他后，旧登记代废止，新登记代只从空址发布；在原路径经正式读口返回原会话的持久 cut。去掉可信原绑定或回收证明、仍有未知对象时拒绝重登；旧登记代再尝试发布也拒绝。 |
| `managed_endpoint_layout_and_legacy` | 受管名字、登记或锁命中 M 时，在文件变更或 spawn 前拒绝；原 R4、坏锚、旧 epoch、独占锁负控保留首错。不能内核核验监听状态的平台拒绝选入；未选入仍按原方式启动或拒占用，X 无本地监听时无新增地址前提。 |

## 不授予的权限

本 ADR 只规定将来获准部署中受管目录项的发布、退役与重登条件。它不授予任何现存进程或账户实际 unlink、宿主目录/挂载/身份变更、隔离、安装、迁移或生产启用权限；隔离 CI 夹具的一次性测试身份和目录不赋予宿主权限。发布助手不持有场所凭据，launcher 原有 X 凭据装配不变。实际资金、下单、场所/账户、风险参数、密钥、凭据与发送权限仍按 [ADR 0041「授权来源与生效边界」](0041-degrees-of-freedom-configurable-not-excluded.md#授权来源与生效边界1909--pr-19152026-11-07) 执行。本票不修改 ADR 0039/0059、缠论和交易判据、R4、既有恢复帽或 #1323 的 Destination。
