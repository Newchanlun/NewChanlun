## 一、范围与现状

本 ADR 只裁验收证据、报告结构和关票簿记，不交付运行证据，不提前关闭 #1279、TB-11（#1369）或任何实施票。

ADR 0063 的迁移协议合入不等于 #1368 与 #1402 的非空迁移、回退与恢复已经验收。ADR 0058 的 AT-14 仓内报告路径继续有效。新整图输入包、整图报告与独立总验报告按现行仓外交付 manifest（`.sandcastle/CODEX-CHILD.md:54, :58-63`）管理，不将某台机器的绝对路径写成永久报告身份。

本 ADR 不签署真实资金、账户或场所激活、量档容量、成本与风险阈值、闸门后参数值及凭据权限；这些事项仍适用 ADR 0036:29-33 与 ADR 0041:46 的授权硬门。

## 二、AT-18 逐项证据与整图覆盖义务

每项 Destination 记录固定包含：Destination 编号与完整义务，实施票、范围与精确 commit，覆盖最终产品差异的非作者独评及所审 commit，实际 `origin/main` SHA 与适用 CI run，按 `evidence_class`（仅限 `simulation`、`experiment`、`production` 三值，拒收 `dry-run`）分列的实体报告引用，下游票状态与剩余义务，以及 `"PASS"` 或 `"FAIL"` 结论。

受测场所、隔离、带仓迁移、闸门后参数与 SPEC 全量覆盖核验须同时满足以下五项接口：

1. **证据类严格分列（ADR 0028:48, :70-71；ADR 0062:104, :258；ADR 0063:78-79, :120；CONTEXT.md:373-375）**。每条验收证据必须标明 `evidence_class`。`P1`（`experiment`，如 `P1-hl-testnet`）证据与 `production`（`P2`）证据在 Destination 记录、TB 汇总与整图报告中分槽记录，不得混记，不得以 `P1` 证据冒充生产有效，也不得将 `P1` 拒发语义外推为 `production` 已裁。已启用证据类槽位统一使用 `ArtifactRef[]` 数组（该槽位在当前记录无条目时填 `[]`）；未启用部署槽位（如本图 #1561 下尚未启用的 `production`）统一填 `null`，不得填 `[]`，并保留「生产首次新发送前」具名门。
2. **Destination ⑤ 权限证据三层与能力 hash（ADR 0062:51-79, :258-259）**。Destination ⑤（「目标部署的隔离和权限证据」及 paper 与 live 共核关系）按受测 `evidence_class` 分列核验三层权限证据：（a）授权声明，即场所 profile 记录中由用户签署的 `credential_scope.class` 与 `authorization` 行；（b）场所权限事实，即 #1770 能力记录 `session_permission` 来源栏登记的场所文档 URL、取回日期与 `sha256`；（c）运行时核验，即 X 库启动记录中发送门第 4 至 7 步核验结果与观测记录。三层分开记录，缺任一层或以一层替代另一层均不得记权限证据成立，Destination ⑤ 必须判 `"FAIL"`；已启用场所槽位缺某层证据或缺能力记录时，按第五节 `PermissionSlot` 规则把该层字段或 `capability_hash` 填 `null` 记录缺失，不把整个槽位填 `null`。整体验收的能力 hash 固定取 `(capability_record_version, capability_record_sha256, venue_profile_sha256)` 三元组，同版本异内容或顶层与 Destination ⑤ 分槽值不一致即判冲突失败。
3. **带仓迁移与回退四项不变量（ADR 0063:120, :123）**。涉及旧入口终态、发送隔离与带仓迁移的核验（Destination ②、③、⑤ 及 #1368、#1402）必须基于非空持仓、未结单、费用尾、中断恢复与回退的实际运行证据，逐项确认不丢权利、不复制资金、不双写、不补发四项同时成立，并按 `experiment` 与 `production` 分槽写入顶层 `migration_invariants`；空仓样例或仅合入协议文书不计通过。
4. **闸门后参数触达与启用三记录核验（ADR 0036:25-33, :42）**。TB-11 整图对账与关图按已启用 `experiment`、`production` 部署槽位分槽核验闸门后参数协议，每个槽位恰好处于 `PostGateSlot.status` 四种状态之一：（1）`TRIGGERED_AND_ENABLED`，该 profile 下已启用阶段能力（`growth_enabled=true`）或声明闸门后参数生效时只能取此状态，必须同时出示同一 `profile_id` 与 `evidence_class` 下持久互引的触达事件（`GateReachedEvent`）、参数版本与首次启用三条记录，且严格满足 `触达.known_at < 版本.authorized_at < 首次启用.known_at`（`TestOnly` 或历史双跑的 `SimulatedGateReached` 不计激活，`experiment` 版本不得自动迁入 `production`）；（2）`TRIGGERED_VERSION_AUTHORIZED`，即已发生 `GateReachedEvent` 且参数版本已授权落盘，但首次启用尚未记录（ADR 0036:28, :33），必须出示触达事件与参数版本两条记录，满足 `触达.known_at < 版本.authorized_at`，并核实 `growth_enabled=false`；（3）`TRIGGERED_AWAITING_POLICY`，即已发生 `GateReachedEvent` 但尚未签署参数版本，必须核实输出保持 `AwaitingPolicy{post_gate_params}` 且 `growth_enabled=false`；（4）`NOT_TRIGGERED`，即该受测运行未触发 `growth_eligible=true`，必须出示未触达与未启用证据。状态（2）至（4）均不按已激活处理，必须在 `bounded_domain_statement` 如实记账，并在 `unexecuted[]` 以 `required=false` 列入该槽位的 `ADR_0036_POST_GATE_EXPERIMENT` 或 `ADR_0036_POST_GATE_PRODUCTION` 条目（常量见第五节 `unexecuted[]`）。本条是 ADR 0036:33「TB-11 关图须出示三条记录」的适用范围读法：对 `growth_enabled=true` 或声明闸门后参数生效的每个槽位，三条记录是必出项；对闸门未触达或阶段能力尚未启用的槽位，关图义务由未启用证据（`non_activation_evidence`）与上述 `required=false` 条目销项。
5. **97 故事、345 family 条目与 496 细项逐项对账（`.chanlun/review-results/issue1340-publication-20260909/view/inputs/TB07-11-EXECUTION-SLICES.md:278, :290`；`.chanlun/review-results/issue1339-r2-spec-20260909/view/spec/IMPLEMENTATION-CROSSWALK.md:5, :115`）**。#1391 必须对照 `IMPLEMENTATION-CROSSWALK.json` 逐条核完 97 个故事、345 个 family 条目与 496 个细项验收输入，写入顶层 `spec_coverage` 供 #1403 逐条复核。crosswalk 条目带 `exclusion_boundary=true` 的 family 条目（所绑定 crosswalk 上是 `OE41` 与 `OE45`）只核排除与防混用边界，其余 family 条目全部是必需条目。`OE42` 是必需条目，#1391 须核实覆盖输入为它登记的 `OUT_OF_SCOPE_PRESERVE` 处分得到遵守（规则见第五节 `SpecCoverageLedger`）。不得仅凭测试计数、子票关闭率或 `N=2` 样例代替逐子义务核验。

组件证据、协议裁定、局部成功、正确拒绝、空域、仅 schema 或未执行测试均不得代替必需成功路径。缺证、跨证据类冒充或射程不符即不得判 `"PASS"`。

## 三、TB-01..11 关票门

关票通用门（`.sandcastle/docs/graph-engineering.md:237-241`）要求票面验收全部满足，全部必需子片交付，非作者评审覆盖最终产品差异，产品进入 `origin/main`，适用必需检查通过，实体报告可读并绑定版本，在制品已有合法处置。失败、未构造、未执行、权限阻塞及跨 TB 未闭合的联合义务必须保留为未完成，不得记为已处置失败。

为消除整图报告生成、#1391 交付关票与 TB-11（#1369）关票门之间的先后循环（`.sandcastle/CODEX-CHILD.md:54`；`.sandcastle/docs/graph-engineering.md:237, :240`），并拦截未经 #1403 独立总验的自报通过（`.sandcastle/CODEX-CHILD.md:74`），`tb_summaries[]` 与 TB-11 关票按三阶段无环推进：

- **`TB-01..TB-10` 独立关票门**。`tb_summaries[]` 中 `TB-01..TB-10` 每项固定核验 TB 编号与票号、全部内部实施子片、按 `evidence_class` 分列的完整外部行为实际运行证据（其中 TB-08、TB-09、TB-10 的 `experiment` 与 `production` 严格分槽，TB-10 并须在自身非空迁移证据上满足 ADR 0063:120 四项不变量）、最终非作者独评、实际 `origin/main` SHA、适用 CI run、各自已落地的实体报告（`entity_reports` 非空，`input_bundle` 固定为 `null`）、剩余义务与票状态。全部满足且票已合法关闭记 `gate_satisfied=true`；任一未满足记 `gate_satisfied=false` 并使整图判 `"FAIL"`。
- **`tb_summaries[TB-11]` 前置实施门（#1391 生成报告时）**。`tb_summaries[TB-11]` 核验 TB-11 自身两张实施子片（#1391 逐项对账与报告生成器、#1403 独立总验器）的实现代码均已进入被审 `origin/main`（`tb_summaries[TB-11].main_sha` 与两项 `slices[].main_sha` 均非 `null` 且为顶层 `head` 在 `origin/main` 上的祖先提交）、适用必需 CI run 结论全部为 `"SUCCESS"`、两子片最终代码差异均获非作者独评 `"PASS"`，并在专用字段 `input_bundle` 中绑定供 #1391 与 #1403 共同消费的 `at18-input-bundle/1` 清单 `ArtifactRef`（非 `null`）。整图业务运行证据归各 Destination、`TB-01..TB-10`、`spec_coverage`、`migration_invariants` 与 `post_gate_records` 承载，故 `tb_summaries[TB-11]` 的 `evidence_by_class` 在已启用证据类槽位固定填 `[]`、在未启用 `production` 槽位固定填 `null`，`entity_reports` 固定填 `[]`，不写入本次 `at18-report/1` 自身路径、`sha256` 或 `content_hash`。正式整图报告由 #1391 在 `OPEN` 状态生成（顶层 `ticket` 固定填 `1391`），报告生成时不要求 #1391、#1403 或 #1369 预先关闭（此时 `tb_summaries[TB-11].ticket_state` 及 #1391、#1403 的 `slices[].state` 均如实记 `"OPEN"`，代码与 `input_bundle` 前置齐备即记 `gate_satisfied=true`）；任一子片代码未进入 `origin/main`、CI 未绿或独评未过时必须记 `gate_satisfied=false`。
- **`#1391` 封包关票、`#1403` 独立总验关票与整图关票序**。#1391 在 `origin/main` 确切 `head` 上产出 `at18-input-bundle/1` 与 `at18-report/1` 后，经 #1391 仓外 delivery manifest（同批登记两份仓外产物）预检通过（退出码 `0`）且获非作者最终独评 `PASS`，先行关闭 #1391。随后 #1403 在独立总验会话中对同一 `origin/main` `head`、#1391 的 delivery manifest、`at18-input-bundle.json` 及 `at18-report.json` 实际运行复核，产出仓外 `at18-verification/1`（顶层 `ticket` 固定填 `1403`，单向绑定 #1391 manifest、`at18-report.json` 与 `at18-input-bundle.json`），经 #1403 仓外 delivery manifest 预检通过且获非作者最终独评 `PASS` 后关闭 #1403。仅当 #1391 与 #1403 依次合法关闭且结论均为 `"PASS"` 后，方可关闭 #1369、SPEC #1340 与 #1323。

## 五、`at18-input-bundle/1`、`at18-report/1` 与 `at18-verification/1`

整图对账与独立总验采用三份具名版本化仓外记录：输入运行包清单 `at18-input-bundle/1`（`at18-input-bundle.json`）、整图验收报告 `at18-report/1`（`at18-report.json` 及从同一份 JSON 确定性渲染的 `summary.md`，人读摘要不作独立判定）和独立总验回执 `at18-verification/1`（`at18-verification.json`）。三份产物均置于仓外持久证据目录，按 `.sandcastle/CODEX-CHILD.md:56-63` 与 `.sandcastle/delivery-bundle.ts:10-17, :27-38` 由所属票的仓外 delivery manifest 以 `storage: "external"` 绑定 `ticket`、`base`、`head`、路径及文件字节 `sha256`；移动或归档后更新 manifest 并重验。

规范化、`content_hash`、提交祖先与封闭类型规则（对齐 ADR 0025:30 与 ADR 0058:193, :208）：

- **`content_hash` 无自指计算口径**。对 `at18-input-bundle/1`、`at18-report/1` 或 `at18-verification/1` 移除各自顶层 `content_hash` 键后，将其余完整 JSON 对象按 RFC 8785（JCS）规范化为 UTF-8 字节串，求 64 位小写十六进制 `sha256` 写入顶层 `content_hash`。`content_hash` 绑定结构化语义内容，仓外 delivery manifest 的 `sha256` 绑定落盘文件完整字节，两者均不产生自指循环。
- **封闭字段集合与升版边界**。三份 schema 的顶层和全部嵌套对象均为封闭字段集合，禁止未声明额外键；总验器（#1403）遇到缺失必填键、类型不符、枚举越界、长度不符、`content_hash` 不匹配或未声明额外键即拒收判 `"FAIL"`。新增、删除、重命名字段或改变字段语义均须升版为 `/2`。
- **`origin/main` 祖先提交一致性**。正式通过报告顶层 `head` 必须等于对账时的实际 `origin/main` SHA；报告内全部 `destinations[].main_sha`、`destinations[].commits[]`、`tb_summaries[].main_sha`（非 `null` 时）、`tb_summaries[].slices[].main_sha`（非 `null` 时）与 `ArtifactRef.commit`（`storage="in_repo"` 时）均必须为顶层 `head` 在 `origin/main` 上的可达祖先提交（`git merge-base --is-ancestor` 为真），否则判 `"FAIL"`。`ArtifactRef.head`（`storage="external"` 时）等于上游仓外 delivery manifest 的 `head`，预检要求该 `head` 等于交付工作区的 `HEAD`（`.sandcastle/delivery-bundle.ts:147`），即合入前的交付分支头；交付按 squash 合入（`.sandcastle/docs/graph-engineering.md:238`）后，该分支头不是 `origin/main` 的祖先。`ArtifactRef.head` 因此必须满足以下两项之一，否则判 `"FAIL"`：（a）它是顶层 `head` 的可达祖先提交；（b）GitHub 记录存在已合入 `main` 的 PR（`merged=true` 且 `base.ref="main"`），其 `head.sha` 等于 `ArtifactRef.head`，且其 `merge_commit_sha` 是顶层 `head` 的可达祖先提交。该 PR 归属 `ArtifactRef.ticket` 的依据是对应 `ManifestRef` 已把同一 `ticket` 与 `head` 绑定，不从 PR 标题或正文推断；PR 按 `head.sha` 查得，报告不记录 PR 编号。（b）项只证明该 `head` 已合入 `main`，不证明 GitHub 把该 PR 记在 `ArtifactRef.ticket` 名下；票归属只取 `ManifestRef` 的绑定声明，由该票自身按第三节关票通用门完成的交付验收认可，#1391 与 #1403 均不得把（b）项成立当作票归属已核实。#1403 独立复核本规则，（b）项须自行向 GitHub 查询，不采信报告结论。

共用子记录封闭类型定义如下（`Sha256Hex` 为匹配 `^[0-9a-f]{64}$` 的字符串，`GitCommitSha` 为匹配 `^[0-9a-f]{40}$` 的字符串，`UtcTimestamp` 为 RFC 3339 UTC 时间字符串，`EvidenceClass` 为 `"simulation" | "experiment" | "production"`，`CiConclusion` 为 `"SUCCESS" | "FAILURE" | "CANCELLED" | "TIMED_OUT" | "ACTION_REQUIRED" | "NEUTRAL" | "SKIPPED" | "STALE"`）：

- `ManifestRef`（5 键）：`{ticket: integer, base: GitCommitSha, head: GitCommitSha, manifest_path: string, manifest_sha256: Sha256Hex}`。`ticket` 为正整数；`manifest_path` 为 checkout 外无符号链接、无 `..` 的绝对路径，文件字节摘要等于 `manifest_sha256`，内容通过 `.sandcastle/delivery-bundle.ts` 的 `deliveryManifestSchema` 校验且内部 `ticket`、`base`、`head` 与本引用完全一致。
- `ArtifactRef`（8 键）：`{storage: "in_repo" | "external", path: string, sha256: Sha256Hex, commit: GitCommitSha | null, ticket: integer | null, base: GitCommitSha | null, head: GitCommitSha | null, bounded_scope: string}`。`storage="in_repo"` 用于仓内规范文件与 ADR 0058 既有仓内报告，`path` 为不含 `..` 的仓内相对路径，`commit` 必填 `origin/main` 上的 `GitCommitSha` 并核验 Git blob 摘要等于 `sha256`，`ticket`、`base`、`head` 固定为 `null`；`storage="external"` 用于仓外持久证据（`.sandcastle/CODEX-CHILD.md:61`；`.sandcastle/delivery-bundle.ts:11-16`），`path` 为仓外持久证据目录下无符号链接、无 `..` 的绝对路径，`commit` 固定为 `null`，`ticket`（正整数）、`base`、`head` 均必填非 `null`，且须在对应 `ManifestRef`（上游仓外证据对应 `at18-input-bundle.json` 的 `external_manifests[]`，#1391 自身产出的输入包与报告对应 `at18-verification.json` 的 `report_manifest`）中存在完全匹配的 `{storage: "external", path, sha256, ticket, base, head}` 条目并校验落盘文件字节等于 `sha256`。任一缺失、不可读、未命中 manifest 或摘要不符即阻断，禁止跨存储方式回退。报告中缺失的必需证据按所在字段的规则填 `null` 或 `[]`，不写占位引用；`at18-verification/1` 的受验引用另按其定义处理。

- `failed_checks[]`（元素类型为 `FailedCheck`）、`permission_blocked[]`（记录受权限阻塞的本图必需成功项，元素类型为 4 键 `{obligation: string, missing_authorization: string, blocker_ticket: integer, evidence_class: EvidenceClass}`）、`bounded_domain_statement`（非空字符串）；
- `overall_result`：`"PASS" | "FAIL"`。

`overall_result=PASS` 当且仅当以下条件同时成立：顶层 `head` 等于被审 `origin/main` 实际提交且全部引用提交满足本节「`origin/main` 祖先提交一致性」规则（`storage="external"` 的 `ArtifactRef.head` 可按该规则（b）项以已合入 PR 的 `merge_commit_sha` 满足）；六项 `destinations[]` 的 `result` 全部为 `"PASS"`、`ci_runs` 非空且适用必需检查 `conclusion` 全为 `"SUCCESS"`、`independent_reviews` 非空且结论全为 `"PASS"`（在全部已启用受测部署槽位上，含本图 `P2` 未启用期间的 `experiment` 槽位，`id=5` 的三层权限证据齐全（该槽位 `PermissionSlot` 四个字段均非 `null`）且其 `capability_hash` 与顶层 `capability_hash` 逐槽相等，顶层 `migration_invariants` 对应槽位的四项布尔值全为 `true` 且 `non_empty_evidence_refs` 非空，顶层 `post_gate_records` 对应槽位满足第二节第 4 条与 `PostGateSlot` 规则，`status` 不是 `"TRIGGERED_AND_ENABLED"`（即为 `"NOT_TRIGGERED"`、`"TRIGGERED_AWAITING_POLICY"` 或 `"TRIGGERED_VERSION_AUTHORIZED"`）时已在 `bounded_domain_statement` 如实登记，并在 `unexecuted[]` 列入该槽位的 `ADR_0036_POST_GATE_EXPERIMENT` 或 `ADR_0036_POST_GATE_PRODUCTION` 条目）；`TB-01..TB-10` 全部 `gate_satisfied=true`、`ticket_state="CLOSED"`、`entity_reports` 非空、`ci_runs` 非空且适用必需检查 `conclusion` 全为 `"SUCCESS"`，`TB-11` 满足第三节前置实施门且 `gate_satisfied=true`、`input_bundle` 非 `null`、`entity_reports=[]`；`spec_coverage` 完整对齐 97 故事、345 family 条目与 496 细项且零项为 `"FAIL"`；`experiment`（`P1`）与 `production`（`P2`）证据在全部字段中严格分槽且无跨类冒充（#1561 未启用期间全部 `production` 槽位均为 `null`，目标生产部署专属的「生产首次新发送前」具名门与生产闸门后三记录门按 ADR 0028:71 及 ADR 0036:33 以 `obligation` 分别为 `ISSUE_1561_P2_FIRST_SEND` 与 `ADR_0036_POST_GATE_PRODUCTION`、`evidence_class="production"`、`required=false` 的两个条目列入 `unexecuted[]`）；七项 `legacy_dispositions[]` 全部满足第四节规则且 `disposition_valid=true`（含 #942 与 #1282 保持 `CLOSED` 及原处分边界、#1320 未完成单列重型测量时保持 `OPEN` 并以 `obligation="ISSUE_1320_HEAVY_MEASUREMENT"`、`required=false` 记入 `unexecuted[]`、#1279 保持 `OPEN` 且 `remaining_obligations` 不含任何本图义务）；`failed_checks` 为空数组 `[]`，`permission_blocked` 为空数组 `[]`，且 `unexecuted[]` 中 `obligation` 无重复、不存在 `required=true` 的条目。任一检查失败必须写入 `failed_checks[]` 并强制 `overall_result` 为 `"FAIL"`。

#1403 独立总验输出的 `at18-verification/1`（`at18-verification.json`）固定为以下 12 键封闭对象：`{schema_version: "at18-verification/1", content_hash: Sha256Hex, ticket: integer, base: GitCommitSha, head: GitCommitSha, verified_at: UtcTimestamp, report_manifest: ManifestRef, report_ref: ArtifactRef, report_content_hash: Sha256Hex | null, input_bundle_ref: ArtifactRef, failed_checks: FailedCheck[], verdict: "PASS" | "FAIL"}`，其中 `content_hash` 采用相同的无自指 JCS `sha256` 口径，`ticket`（正式总验固定为 `1403`）、`base`、`head` 与 #1403 的仓外 delivery manifest 一致且 `head` 等于被验报告与输入包的 `head`，`report_manifest` 绑定 #1391 登记 `report_ref` 与 `input_bundle_ref` 的仓外 delivery manifest，`verdict="PASS"` 当且仅当 `report_manifest`、`at18-input-bundle.json`（含 `external_manifests` 全部上游 manifest）与 `at18-report.json` 通过全部封闭 schema、`content_hash`、文件字节摘要、`origin/main` 祖先提交一致性（对 `storage="external"` 的 `ArtifactRef.head`，#1403 自行向 GitHub 查询 PR 的 `merged`、`base.ref`、`head.sha` 与 `merge_commit_sha`）、97 故事与 345 family 条目及 496 细项逐条覆盖、ADR 0036 三记录门与业务判据独立复核且 `failed_checks` 为 `[]`。`report_manifest`、`report_ref` 与 `input_bundle_ref` 是受验对象，照录 #1391 交付登记的值；本节对 `ManifestRef` 与 `ArtifactRef` 的可读、命中 manifest 与摘要相符要求在此是 #1403 的核验项，任一不符写入 `failed_checks` 并判 `verdict="FAIL"`，回执仍按本 schema 输出。`report_content_hash` 是 #1403 按同一口径对 `at18-report.json` 自行重算的 `content_hash`；该文件不可读或不是 JSON 对象时填 `null` 并判 `verdict="FAIL"`。

TB-11（#1369）、SPEC #1340 与 #1323 的关票须在 #1391 已生成 `overall_result` 为 `"PASS"` 的 `at18-report/1` 并完成 #1391 封包关票、#1403 已对该报告与 `at18-input-bundle/1` 实际运行产出 `verdict` 为 `"PASS"` 的 `at18-verification/1` 并完成 #1403 封包关票、两份仓外 delivery manifest 校验均通过（退出码 `0`）且两票最终非作者独评均为 `PASS` 后执行。关票评论须同时写明 `at18-input-bundle.json`、`at18-report.json`（路径、文件 `sha256`、`content_hash`）与 `at18-verification.json`（路径、文件 `sha256`、`content_hash`、`verdict`）、双方 delivery manifest 路径与 `sha256`、实际 `origin/main` SHA、适用 CI run、最终非作者独评、六项 Destination 证据摘要、ADR 0036 各槽位的 `PostGateSlot.status` 与对应记录、`unexecuted[]` 明细及七张旧票去向；缺任一实体报告或独立总验未通过时写「无有效总验报告」，不得声明整图通过或关闭 #1369、#1340、#1323。
