本条依 #1909 代理独审裁定

状态：第 2 轮，待异家族非作者独审。首稿 666a1a42 的 R3、R4、R5 BLOCK 已按「4. 独审」进入一次重做；本稿不能发布为 resolution 评论。

## 问题

#2079 要裁谁可在上一进程正常关停或崩溃后重新提供原会话端点，保留原路径和业务状态。#1823 的两种构建各在三种布局确认 S 的首错是参数期路径占用；#2077 正常关库仍保留路径。首稿的局部故障和 launcher 崩溃结果不够确定，未知登记状态缺出口，平台监听证明可能降级。三项都需要确定的结果，不靠放宽判据解决可用性。

## 权威依据

- ADR 0039 裁定三管装配、监督、换代；ADR 0059 裁定第 1–4、6–10 条管 M、canon、启动前拒绝及禁用放行开关。C09.3、C09.7–9 与 ADR 0038 #1539 修订管局部隔离、写者代、X 退出和外效。
- 具名 E/B 恢复先例 #2082 只绑定该候选头的全 E/B 计划；不是局部恢复接口。#2077 的有序结果仅 S/E/B，控制管道 EOF 不等于关停。
- ADR 0041:11–15 和 #799 禁同一判断松紧两版与失败降级。#1823 的观察、排他反例、SAFE 规格与原始探针按「引用自证」核对。

## 候选

- 采纳同址、逐域逐代新监听器。Linux 夹具确认原址两代答复、名字写权分离、旧待受理连接断开。保留 FD 会把旧队列交给新进程；改址与只比 PID/inode 再清名均不满足合同。
- 不在本 ADR 自动重拉一域。选入时 launcher 隔离失效域并持续服务健康域。单域重拉及局部写者凭证交 #1411，避免把 #2082 的完整 E/B 计划错套到健康域或把 E 来源代当作端点代。
- 拒绝由新 launcher 自证旧作业已回收；只认独立部署监督器。登记恢复不从现场认领不明对象。只用内核验证收到的 FD 已监听，未知/错误时不切换证明。

## 裁定

正本落点：docs/adr/0065-production-session-endpoint-rotation.md

仅在原部署入口显式选入的同宿主版本生效。部署监督器保持会话作业排他并核回收，发布助手只对完整登记且证据匹配的旧 socket 做原址换代。launcher 活着而一域退出时，只隔离不重拉；未选入保持原监督语义。launcher 崩溃后，监督器证明旧作业与 FD 全部回收才能接续，否则不启动、不改名字。宿主重启的 boot ID 只证明旧进程和 FD，不证明路径归属。「端点需恢复」由监督器封堵旧代并给重登许可；发布助手确认原址为空、排他和原绑定可证后，在一次登记提交中记旧代废止并开启新代，已有不明对象走独立运维授权。收到 FD 必查内核 SO_ACCEPTCONN，平台不支持或核验失败均拒绝。持久代等于原 manifest 代时无需额外回执；已换代的只消费本域当前核验的正式凭证。

的目录项身份和完成状态。两份记录与互斥状态都放在 S 测量和业务库之外，不存于会随 socket 目录消失的临时文件系统。初次登记须确认原址为空；不能把直绑遗留或不明对象补登记为受管资产。\n2. **排他。** 从核验到名字变更及状态提交，发布助手须持有该目录项的排他资格。部署持续禁止域、客户端、旧入口及同发布身份的其他作业绕开互斥。绝对路径从根到最终条目不得经符号链接、`.` 或 `..`；锚及可改变解析结果的祖先、挂载和权限须受保护。用无法改写锚的域身份与专用发布身份分离目录写权；同 UID 可绕过时，`0700`、协作锁、PID 或 inode 都无效。锚、挂载或发布身份变化即失去旧登记的名字操作资格。\n3. **先记意图，再改名字。** 只有前代回收、排他、保护连续性和完整登记同时成立，且原位置确为登记的同代 socket，才允许发布助手 unlink 该目录项。先持久记录绑定旧对象的退役意图，退役后记完成；确认空址后另持久记录新端点代的发布意图，再原址 bind。只有已记 `已发布` 及具体目录项身份才交 FD。设备号、inode、类型和属主用于查错，不是处置权来源；目录项 inode 也不是监听 FD 的 inode。\n4. **中断按证据续接。** 有退役意图时，只有旧对象和退出证据仍匹配、排他连续才续做；若原址已空且上述退役意图和排他连续仍可证，补记退役完成。仅有发布意图、现场为空且可证本次作业及 FD 回收时，结束该次尝试，以新端点代重试。bind 后已有对象、却未写完 `已发布` 时，报「端点需恢复」并保留原对象：发布意图没有成功 bind 的身份凭据，排他不能补这条绑定；退役意图则已引用完整登记的旧对象。完整登记对应的对象消失、发布日志丢失、对象被替换或保护失效也报「端点需恢复」，不猜测、不自动移动或删除。\n5. **「端点需恢复」的出口。** 由部署监督器封堵旧登记代的作业和发布资格，核对独立部署记录或其可信恢复原件，证明前代回收。发布助手在本次获准部署的排他范围内重验原址、当前锚与保护。部署监督器先持久记录旧代封堵和本次重登许可。确认原址为空后，发布助手依该许可在同一笔登记提交中记旧代废止及其凭据、开启新登记代。登记提交后方可按空址首次发布；重试同一许可只续做该次重登，不再开一代。临时目录因同宿主换 boot 而消失时，先由已获授权的部署动作备好原路径的受保护锚；不可借旧登记动现场。只有发布日志丢失、仍能用独立部署记录定位前代时，才可这样重登。连原会话的部署/登记绑定或封堵也无法恢复，继续拒绝。原址上若仍有对象，另由具备独立授权的运维处置；本 ADR 不准发布助手认领或移除它。等原址确认空、其他前提也成立后，才执行上述作废与重登。\n6. **FD 定向交付和内核核验。** 发布助手与 launcher、launcher 与域的交付均使用定向继承白名单或已认证的私有通道；部署、域、登记代、端点代与同次 FD 一起绑定在该私有启动交付，不由公开请求提供。接收者核来源、域、代、`AF_UNIX`、`SOCK_STREAM`，并核 `getsockname` 的绝对地址字节等于预检通过的原 manifest 地址。**接收者必须直接向内核查 `SO_ACCEPTCONN` 且结果为真。** 不支持该核验的平台不属于受管模式支持范围，选入即拒绝；对具体 FD 查询报错或返回 0 均拒绝，不改走其他证明。错传、多传或拒绝时关闭相应副本，正常交付后上游释放多余副本；兄弟域、客户端以及后续 exec 不得获取 FD。域按原协议服务，不再按名字 bind 或 unlink。\n\n## 先做布局核验，再接业务恢复\n\n[ADR 0059 裁定第 1–4、6–10 条](0059-production-session-layout-contract.md#裁定) 继续管路径解析、布局、前置拒绝和禁用放行开关。直绑 S 的第 6 条例外依赖 S 打开 driver 后才 bind；受管模式不能借用。正式入口在改名字、传 FD、建域文件或拉起写域前，只读核验受管地址、登记、角色和布局。受管 S、E、各 B、适用 X 及登记、发布、互斥写足迹避开测量域 M：`P` 目录本身、`P` 内 S 族条目及其子树、`A` 及其子树。检查目录项所在和实际目标目录，不扩大到 `P` 的其余子树。命中即 `InvalidDomain`，点名字段和地址，不做变更。既有 `state_dir` 例外不用于存放受管发布状态。接 FD 仅换传输装配；各域原有的资源、媒体、持久身份、锁与 R4 核验照常运行。\n\n**端点代不等于会话代或持久写者代。** 整会话从原 manifest 字节及其引用的域配置确定静态会话、库和身份。若本域持久写者代仍等于 manifest 代，沿用该代，不要求额外恢复回执。若需要推进或已不等于 manifest 代，只从该域对原配置、库、域、前代与当前代核过的正式恢复凭证取值。若恢复已提交却丢回包，用同一恢复身份取回原件并核其仍授权当前代。不能改原 manifest 的 epoch、读整数手加一、借历史回执或端点代赋予写权；`serve` 持本域锁后仍须核当前持久代。\n\n#2082 候选 `329be34f5a9ca9c2bcc38ae75783304cc654904c` 的 `--economic-recovery-plan` 示范整会话 E/B 的显式当前回执装配；B 分别得本域与 E 来源代。#1411 负责接齐各域凭证（含 S/X）、处理原代与恢复后代混合的整会话，并核同一会话的 E 来源身份；不以全 E/B 计划强行给无需换代的域升代。故障隔离、各证据类恢复和外效保留继续按 [SPEC #1340
