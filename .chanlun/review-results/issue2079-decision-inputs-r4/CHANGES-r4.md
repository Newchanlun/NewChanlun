## R3 四点

| 独审要求 | 落法 |
| --- | --- |
| a．明确定义写入 | ADR :34–36、:52：受管 launcher 的 `domain-stopped` 新带 `run_id`、域 `pid`，只由 launcher 可写的私有 stderr 交给独立部署监督器。监督器核当期作业与实例，原子写入受保护持久卷上的 `production-session-deployment/1.domain_exit_results`，逐条绑定会话键、作业、旧 boot、运行、域、PID、进程启动标识、登记代、状态与关库结果。 |
| b．明确定义读取 | ADR :23、:38、:57：旧作业及 FD 回收证明齐备后，新 launcher 只读私有交付的紧邻前代记录；域结果未持久提交、错绑或冲突走异常列，从不回退读 stderr。整作业证明或独立部署记录缺失直接拒绝接续，不用异常列放行。 |
| c．二值分支与错代负控 | ADR :38、:95：L2 实际派发时记录 `managed-recovery-selection`；E 强杀后只留下旧 `run_id` 的成功结果，E 必须走异常并核当前回执，正常 S/B 保持有效代，B 单独核 E 来源代，原址 cut-1 与 input-2 验完整闭环。 |
| d．宿主重启取证 | ADR :89–91、:99–100：VM 外控制器真实重启同 guest，新监督器从原持久卷读回前代记录；不交旧 stderr。匹配结果选正常，缺某域结果选异常；boot ID 只证前代退出，不证正常关库或目录项归属。 |
