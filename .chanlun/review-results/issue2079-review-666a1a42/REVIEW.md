## 必须修的五项

**1. R3：崩溃验收缺执行者和预期结果（:21-24、:32、:45、:64）**

- main 的 `production_session.rs:11` 和 `:327-336` 规定任一 S/E/B 退出即回收全部子进程。ADR 要求「只接续受影响域、健康域仍提交」，但没写谁单独重拉起一个域。
- launcher 被强杀后域进程成为孤儿继续运行。launcher 没有 PDEATHSIG 或进程组联动，#2077 也写明 EOF（含 launcher 崩溃）不是关停请求。第 3 条又禁止二次发布和为清名杀进程，所以这一分支是拒绝还是接续、谁出具回收证明都没有写。
- #2082 的计划要求 E/B 一一对应，单域接续的写者代凭证没有来源。

最小修：
- 写明选入部署下由 launcher 监督循环只重拉起退出的域，并说明这改变了现行「任一退出即会话失败」。
- 把 launcher 崩溃的两种结果写进验收行：部署监督器证明前代全部作业与 FD 已回收时，按崩溃列接续各域；任一孤儿仍在或无法证明时，拒绝并保留现场。这一分支必须有部署监督器，不能只写「可以用」。
- 写明单域接续的 E/B 写者代凭证来源，或把它排除出本验收并指向承接票。

**2. R4：「端点需恢复」没有出口（:30、:31、:34，连同 :13、:17）**

- 第 2 条给的出口是「重新走部署登记」。第 1 条禁止对已有对象补登记，:17 的判重不许两条登记指向同一目录项，全文没有旧登记项怎样作废。
- 这些普通情况会让原端点永久不可服务：bind 后写「已发布」前崩溃；状态是「已发布」但对象已不在（宿主重启后 tmpfs 清空、锚目录被重建）；记录丢失。选入后又不许退回直绑。

最小修：
- 补一条出口规则：谁、凭什么证据把旧登记项记为作废并开新登记代。现场仍有对象时，移除走本 ADR 之外的单独授权，不新增 unlink 权。
- 裁定宿主重启是否算可证明退出，以及证据形式（例如登记绑定 boot id）。
- 说明 bind 窗口为何不能像退役窗口那样凭排他连续性认领，或改为允许。
- 在 :65 加一行从「端点需恢复」回到可服务的正控。

**3. R4：分支 diff 与编辑合同不符（落地形态，不改正文）**

`git diff --name-status origin/main...666a1a42` 列出 9 个新增文件，canonical-plan 只建 ADR 0065。多出的 8 个在 `.chanlun/review-results/issue2079-endpoint-rotation/`，含未审的 DRAFT.md。原因是父提交和 sourceCommit 都是证据提交 5a1ac9de。

最小修：以 origin/main 为基重建分支，只含 ADR 一个文件；canonical-plan 的 sourceCommit 和 draft.md 验收 1 的基底改为 main；证据留在证据分支。

**4. R4：头部缺日期和受影响代码清单（:3-5）**

R4 条文点名要核这两项，ADR 0059–0063 都有。改成「正本／最后裁定（含日期，P 类，依 #1909 代理独审裁定，非 UserSigned）／受影响代码清单」。清单至少列 `production_session.rs:11`、`:327-336`、`:398-440`，S 与 E/B 的 bind 点，`history_simulation/runtime.rs:866-897` 和 `rust/tests/production_session_entry.rs`，行号按落地基线逐条核对。

**5. R5：监听状态的两种证明（:35）**

「当平台不提供 SO_ACCEPTCONN 时，用受信创建过程证明」没写切换条件是事前固定还是运行时看报错，也没定义这种证明。EVIDENCE.md:31 记录 Darwin 是运行时报 ENOPROTOOPT 才得知的。按 ADR 0041:11、:13，同一判断不得有松紧两版，更不得失败后改走另一版。

最小修，二选一：
- 删掉这句，改为「接收方不能向内核核验监听状态的平台不属于受管模式支持环境，选入即拒绝」。
- 保留平台差异：证明方式按平台在获准部署版本里事前单选；提供 SO_ACCEPTCONN 的平台上，任何报错或返回 0 都拒绝；写明另一种证明由哪些记录组成、谁核验、不能核验即拒绝，并附退场条件。
