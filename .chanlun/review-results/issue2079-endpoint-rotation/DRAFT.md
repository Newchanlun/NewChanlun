# #2079 裁定草稿｜原路径由谁重新提供

**建议选「同一公开路径，每域每代新建监听器」。** 对明确选入且部署条件成立的会话，由 ADR 0039 的唯一 launcher 经受信部署入口发布端点；S、E、各 Bᵢ 及实际提供端点的 X 只接收属于自己的监听 FD。关闭上代最后一个监听 FD，不把上代内核队列交给下一代。客户端继续使用 manifest 中的原绝对路径、原消息和原业务身份。该选择增加的是端点名字的发布责任，不是新的业务进程、数据库写权或外部调用权。

建议按 **P 类**提交独审：这里第一次划分 OS 发布权限，而不是解释一条已有的清理权限。图 #1323 的 N‑1 决策程序适用于设计稿；真实目录/身份配置、安装、生产启用和账户权限不在本票。本稿待绑定正文的非作者审查，未签准。

## 选择依据

- [#1823 六份 CI 收据](https://github.com/Newchanlun/NewChanlun/issues/1823#issuecomment-6687775294)：两种构建 × 三种布局，杀 S 后再次启动首先在 S 参数检查报「socket路径已占用」，还没到 R4。[#2077 R2](https://github.com/Newchanlun/NewChanlun/pull/2077) 则证实正常关停可让 SQLite 自行收掉 WAL/SHM，原库仍在 cut-1，原路径仍在；第二次启动同样拒绝。修关库不能解决名字归属。先比 PID、设备号、inode 再按路径删除，在他人可改名的目录中仍可能删错，[已有非作者反例](https://github.com/Newchanlun/NewChanlun/issues/1823#issuecomment-6994092216)。
- **每代换监听器**：隔离 Linux 中，两个不同的域进程通过 FD 先后在同一绝对路径答复；域身份能 connect，却不能创建、改名或删除该目录项。上代未受理但已写入的连接收到 ECONNRESET，下一代只收到新连接。[实跑原件](linux-fresh.log)。
- **另选项：部署托管者跨代保留一个监听 FD**。Darwin、Linux 都验证可行；路径甚至保持同一 inode。但是两层应用进程都换过后，新 worker 实际收到了停机空窗写入的原字节。选择这种做法就要另定跨代排队、丢弃和恢复授权；不能用「仍可连接」代替新代就绪，也不应为了排空一个域而让其他域共同停机。故不作此次默认。[Darwin](darwin-fd.jsonl) / [Linux](linux-fd.jsonl)。
- **保留既有 pathname bind**：作为未选入部署的默认行为，保留已有路径拒绝。轮换私有路径、使用 Linux 抽象名或重建运行目录即使使 bind 成功，也不能证明原客户端仍能按原 manifest 找到同一会话。

## 谁能改变名字

1. **部署注册，先于首次发布。** 绑定不可变的会话配置、部署实例、域和角色、公开绝对路径、锚定目录及专用发布身份；登记文件在 S 测量与业务库之外，由同一受信边界持久保管。路径对应 S 的 `s.socket`、E 的 `e.socket`、按 chong 身份匹配的 B socket、以及所选 X profile **实际声明并提供**的 socket；无 listener 的 X 不造一个。不同域不得映射到同一名字。首次接管只能从已注册且确认空的名字开始；不能把原址一个陌生 socket 补登记为已有资产。
2. **排他来自 OS 和部署，而不是 inode。** 锚定目录和所有能改写其解析结果的祖先/挂载受保护；域进程、旧 launcher 直接入口和客户端均无创建、替换、搬移、换父目录或改变该保护的权限。部署只允许一个受信发布者在同一域上执行发布/退役，并保证其他具备该身份的进程不能绕开这次互斥；重启前后连续成立。可用专用服务身份及不可被域改名的目录，配既有部署管理器的单实例作业，域以另一非特权身份只获 FD。路径按受保护锚无跟随检查；拒绝符号链接和模糊归属。不需要生产 root；管理员改锚、权限或更换挂载后须重新登记。普通同 UID 进程仍可写时，即使 chmod 0700 或 launcher 之间用 flock，也不算成立。
3. **登记按域独立。** 在排他期间留存发布意图、前代/新代标识、已实际 bind 的受控目录项身份和发布完成记录；退役亦留意图及完成记录。每次改变名字之前先持久化意图，核对保护连续性、注册和状态。设备号/inode/类型/属主用于查错，不是所有权来源；亦不得把文件系统 inode 当作内核 FD inode。若遇 bind 成功但记录尚未完成、意图与现场不一致、停机证据丢失等未能证明的窗口，保留现场并报告「端点需恢复」，不推断失主、不给清理权限。实现可用按域持久日志或既有部署管理器等价原语，须验异常中断。
4. **持 FD 不等于有发布权。** launcher 对明确指定的子进程用继承白名单或已认证的私有 FD 通道交付且仅交付本域 FD，校验域、代、类型、绝对地址与监听身份；其余进程不可获取或转交，后续 exec 不继承，发布方释放多余副本。不得开一个凭共享目录里任意客户端就可领 FD 的入口。域不按名另行 bind/unlink；它保留原协议、验证、超时与资源界限。受信发布者不需场所凭据，不代 X 发送。

## 原 manifest 的下一次启动

**先做只读布局核验。** [ADR 0059 Q1](https://github.com/Newchanlun/NewChanlun/blob/b9d898dccf46c2a716115eaa1215bc39c458a959/docs/adr/0059-production-session-layout-contract.md#L103-L123) 允许直接模式在 S 自检后 bind；受管模式可能更早创造目录项，故必须先核全部声明、角色、发布边界和计量布局，再动名字、传 FD、初始化或启动写域。受管端点及登记、锁等副作用不能落入 S 的捕获边界（P 的测量条目、A 子树、S 族等；沿用原精确定义，不把整个 P 子树扩成禁区）。不因接收 FD 跳过 R4、既有资源/媒体核验或业务身份核验。

| 再启动看到什么 | 受管发布者怎样做 |
|---|---|
| 正常关停，名字仍在，且前代及持 FD 的后代已退出 | 核域级关停收据、部署作业的退出/回收和 FD 保管边界；在同一排他期对准登记与原对象才退役原名，原址 bind 新 listener。新 worker 走正常恢复；收到新代真实就绪前不宣告服务。 |
| 前代/另一发布者还活着，包括暂停、超时不响应 | 拒绝第二次发布；不移动名字、不抢 FD、不打断原服务。PID 消失、探测超时、尚未 connect 都不构成退役依据。 |
| 经过 SIGKILL 或发布者崩溃 | 标明异常而非正常交棒。监督器能核实旧域作业/后代已经退出、无越界 FD 副本、登记和名字权仍连续时，才可进行同域端点交替；数据只能走该域正式 crash recovery。残留 SHM/WAL 不由端点裁定清理；恢复失败保留其真实首错，不宣布 Ready。 |
| 未登记、替换、失去写权排他、不明对象/代/父目录，或不能证明旧进程退出 | 拒绝并保留原对象；不以改名隔离代替删除，不删后再试，不扫描相邻路径。之前已通过的文件身份比对不改变此结果。 |

**两个不同的代际要各有来源。** 端点代只标识哪个 listener 接受连接。S/E/B/X 自己验证数据库身份、锁和持久写者代际；X 换代核旧发送者及其子进程、排他发送身份和 MayHaveCalled/在途账。旧连接中已接纳而未收到回复的请求，按原身份查询/重发；断线不等于未提交，不撤销责任。

同一份不可变 manifest 不是复用已失效的 epoch。当前 [launcher](https://github.com/Newchanlun/NewChanlun/blob/b9d898dccf46c2a716115eaa1215bc39c458a959/rust/src/bin/production_session.rs#L397-L445) 逐值把配置里的 epoch 传给 S/E/B/X；例如 [E/B recover](https://github.com/Newchanlun/NewChanlun/blob/b9d898dccf46c2a716115eaa1215bc39c458a959/rust/src/economic_session/store.rs#L1694-L1725) 将新 epoch 持久化并返回收据，[serve](https://github.com/Newchanlun/NewChanlun/blob/b9d898dccf46c2a716115eaa1215bc39c458a959/rust/src/economic_session/service.rs#L1514-L1518) 会逐值核验。建议**仅在选入的恢复入口**，让同一原 manifest 确定静态会话、原库、身份和获准恢复方案，再由每个域的正式恢复收据提供本域有效代际（B 如需 E 的代际亦须取对应有效收据）。收据须绑定该 manifest、库/域身份、前代与恢复后代，由该域核对原持久记录，不能以读当前整数、手加一或端点代自行替代。恢复已提交但答复遗失时按原恢复身份核查，不能盲目再升一代；无法证明则保留待恢复。**这项接线须与 #1411 恢复 owner 单独签定并实测**，否则只可称原路径恢复，不能称完整会话恢复。同样，不能编辑 manifest 的 epoch 字段再称“原 manifest 重启”。

S、E、每个 B 和 X 分别出具本域就绪/拒绝。全会话只有全部必需域的既有就绪条件成立才称 ready；单域恢复不能等待其他域恢复或共用其事务/恢复锁。S 的实际新实例须能回答具名读请求；E/B 查域、锁和持久身份；无读口的 X 沿用既有 profile、持锁、持久身份与进程检查，不杜撰 Ready RPC。端点存在、可 connect 或已 listen 都不是业务就绪。[SPEC C09.3、C09.7–9](https://github.com/Newchanlun/NewChanlun/blob/efc1ddc4d6c015f4f8c6d44f904d704a88308b46/.chanlun/review-results/issue1339-r2-spec-20260909/view/spec/SPEC.md#L325-L334)；数据与外效按 [ADR 0038 修订](https://github.com/Newchanlun/NewChanlun/blob/b9d898dccf46c2a716115eaa1215bc39c458a959/docs/adr/0038-dual-run-determinism-recovery-seek-asknown.md#L134-L139)。

**未选入部署保持原合同。** 不给已有 manifest、直接 pathname bind、独立 serve、原 wire 调用增加目录/登记/FD 前提。[现有 S](https://github.com/Newchanlun/NewChanlun/blob/b9d898dccf46c2a716115eaa1215bc39c458a959/rust/src/bin/s_session_v3/writer_cli.rs#L382-L395) 对已有路径继续给出原首错。部署若把 socket 和需由不受信域写入的 SQLite 放在同一可写目录，或各角色实际同 UID 且无有效隔离，不具备本方案的自动接管条件。需要改目录、服务身份或原地址时另签 provisioning/迁移；只迁了地址不能登记成原址恢复。

## 实施验收：以同库第二笔提交作为成功线

沿用 [#1823 OBS/SAFE 规格](https://github.com/Newchanlun/NewChanlun/issues/1823#issuecomment-6550850441)，在精确实现头和明确选入的无外效部署验收：

1. **有序重启**：L1 由正式入口首次提交 input-1，留存原请求、完整回执、库身份和各域身份。正常关库，确认子进程收回。不同的 L2 以同一份 manifest 原字节、相同路径、原库和相同会话启动；出示各域有效恢复收据及真实就绪。经正式读口固定 cut-1，完整原收据逐字节相同；再给原会话 input-2，原始应答为 Committed，查询其持久提交。原身份重送不重复经济效果。不得用 SQLite meta 的 cut 数字、空库或不同 manifest 代替。
2. **异常和局部恢复**：原有 SIGKILL 三种布局保留首错。合法布局分别杀域/launcher，含旧 sender 尚存和已持久接纳未获回复。只在前述归属与业务恢复均能证明时重开受影响域；其他健康域在单域恢复场景仍处理自身工作。异常不发有序关库收据；保留 MayHaveCalled，simulation 与 experiment/production 各遵原有恢复语义，无真实调用。在 bind/登记、恢复提交/收据交回等边界插入确定中断，核已知状态能恢复，未知状态保留。
3. **SAFE-LIVE / UNKNOWN / RACE**：活实例、暂停、PID 复用、替换、错域、错 uid、未注册对象、symlink/替换祖先和不受保护的同 UID 部署，均不得触碰对象。在核验到退役间设置确定同步点；未授权改名必须被 OS 拒绝，不能靠操作恰好没有撞上；第二个受信发布作业不能同时进入。定向错传/多传 FD 必须拒绝、兄弟域不能得到 FD；旧代排队不能在新 handler 触发。异常后的业务重试依原身份办理。
4. **SAFE-ADMISSION / 原入口对照**：受管非法位置在 spawn、域写入、改名字前拒绝；保存 R4、锁、旧 epoch、坏锚的原拒绝与现场。对未选入 profile 跑原 CLI、有占用拒绝及布局对照；对无 listener 的 X 不新增 socket 要求。

这四组是实施门，不是已经通过的项目测试。本次 [可行性实证与复跑方法](EVIDENCE.md) 只确认 OS 层两种交接的队列和权限行为。不能用它们关闭 #1411 或替代 #2077 的限域验收。
