# 对 #2113 的收口要求

**交付声明**（双入口校验与实测都通过后使用）：

> Linux 上，采用合法 X 凭据键名时，打开持久库启动的 `stat` 的初始执行环境除原有 `PATH`（如有）外没有任何继承项；由 X 执行 profile 注入的凭据不可能编码成内核键 `PATH`，不会到达 `stat`。

「由 profile 注入」限定的是同一注入通道；不对外部进程把同一串字节另行放进 PATH 作承诺。PATH 未设仍未设，空串仍为空串，稳定且唯一时按原字节保留。macOS 按 `rust/src/economic_session/store.rs:470–501` 直接走 `statfs`，没有这个子进程；其他目标仍遵 ADR 0039 隔离原则，未验证目标不计成 Linux 验收证据。

| R4 反例 | #2134 裁定后 | #2113 的验收 |
|---|---|---|
| HIGH：配置名不同于 PATH 但内核键相同 | 两端同判拒绝字面 PATH、所有含 `=` 名及其他不合规名。允许域没有分隔符，序列化的首个等号只可能是键值边界，且首段是专用名。经 profile 注入时不可达。 | 从实际 launcher 和单启 X 覆盖字面及别名、起首等号；新旧 schema 在各自落地时共用键名用例。 |
| MED：`vars_os()` 漏枚举的原始空名/无可解析分隔符项 | 不可能由合规 profile 经 clean launcher 生成；**外部以合法 profile 单启 X 仍可到达**，例如不需要凭据的 simulation，只带普通 PATH 和一个未被枚举的原始项。R4 在零删除时仍传原向量。 | 在内核初始环境边界检查原始项计数与 PATH 字节，覆盖零可删键、PATH 未设、有一个普通非 PATH 键、合法 profile 直接启动。必须消掉 MED 才能使用上面的声明；不能用“键已合法”或仅查 `vars_os()` 宣称修复。 |
| LOW：测试宿主哨兵导致误入子模式 | 非键名合同 | 子模式绑定本次夹具的私有目录和操作，并在开库前确认；外部一般环境不能触发。 |

实现与检验要求：

1. 在 `rust/src/bin/production_session.rs:177–192,251–277,440–448` 与 `rust/src/bin/x_execution_session.rs:37–63,193–222` 共用同一无副作用谓词。只校验 profile 字段，既有版本继续读自己的 schema；实现 /2 的工作复用该谓词，#2113 不为此先行实现 ADR 0062 全套发送门。坏键在 launcher 读文件/建状态/任何域 init 或 spawn 前拒；单启 X 在持锁、开库/执行 stat、环境读凭据前拒。不要移动合法键缺凭据原有合同。
2. 建议集成测试 `invalid_x_credential_key_refuses_before_side_effects`：同一键矩阵对拍两个真实入口；包含缺失、非字符串、空、等号、NUL、空白、非 ASCII、文字 PATH、动态加载键、非命名空间的常规键、合规基本名及后缀、64/65 字节边界。对不合法输入用隔离、可观测的合成文件哨兵（例如对凭据文件路径捕获 open，或 FIFO 读检测），同时断言无文件打开、无 launcher 状态/域 spawn、无 X 锁/库/探测子进程、双方 `InvalidDomain`、不回显输入。合规样本仍证明 X 能启动及 credential 只在 X。迁移 `history_simulation_entry.py:123` 的占位键并运行现有入口测试。
3. 建议 Linux 测试 `durable_db_stat_preserves_only_path` 扩展原始环境边界采样。以 R4 保留标准库查找与 spawn 为基线，不把手写 PATH 搜索、固定 PATH、无条件 `env_clear().env("PATH", …)` 或旧 glibc 豁免当捷径。特别要区分“零个键被删除，所以没有重建”和“重建后的环境只含 PATH”；机制由 #2113 提出和验证。对受支持的正常环境核对 PATH 未设/空/值、查找与退出状态、stdout、错误文本、子进程数、文件系统放行集合，并跑先前暴露差异的 glibc/musl、资源限制和 E/B 辅助进程对照。原始 envp 下重复 PATH 不是可移植输入，#2113 应记录其观测和处置，不借矫正异常输入改写正常唯一 PATH 的查找语义。生产 X/E/B 启动后不动态修改进程环境是 R4 经调用链核过的前提；若实施改变该前提，须相应修正过滤与证据。
4. B13 使用 #1383 的全树内核采样（`2de3a4694a174db312aac6644f92011a058da2aa`）在两档构建真实执行 `credential_key_only_in_x_child`；确认删除过滤或故意保留另一普通键的负控会失败。保留 B13 原验收的 launcher 启动环境键集登记，仍由 #1383 所有，不以本票或一次 stat 样本代替。没有真实凭据、端点或资金操作。
