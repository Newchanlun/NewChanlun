## 必须修的三处

**1. R5：旧合同路径上关库标记不消费（:53，连同 :30、:61、:89、:103）**

- :53 把消费点写在「认领成功后、首个 accept 前」。:30 说旧合同「不做新认领」，对库只留一句「库门仍对所有平台生效」。:61 把消费与「新认领成功」连写，:89 只写「标记门仍生效」。
- 照字面实现，非 Linux 或目录不合格的 E/B 直绑后带着本代标记服务。被杀后只要残留被清掉，下次 serve 过标记门直接服务，不经正式恢复。清残留不用等 #2130：仓内 `economic_service_control.py:86` 的 `prepare_socket` 现在就会删，tmpfs 重启也会让它消失。
- 这与第四稿被拦的旁路同型，违 C09.9 和票面「异常退出不得冒称干净交接」。九项验收都在 Linux `0700` 目录上跑，两种读法都能全绿。
- 最小修法：:53 改为 E/B 在任何路径（认领表或旧合同直绑）bind 成功后、首个 accept 前消费标记，失败即关监听、非 0 退出。:30、:61、:89 同步。`clean_close_negative` 加一臂：旧合同目录（如 `0770`）下 serve 后真杀并清掉残留，再启须报缺标记。

**2. R8：考古漏了在案先例（考古 Q3/Q4；ADR :5、:28、:45、:60、:127）**

- main 的 `s_session/s_service_control.py:505–528` 对残留 socket 的规则是：owner 停止记录加登记的 dev/ino/uid，试连只认 ECONNREFUSED，删前重核，然后按名 `unlink`（:527）。`start_s` 和 E/B 的 `economic_service_control.py:86` 都调用它。#1372（已关）交付时经 PY-XR-02 非作者复核闭合。`session_transport.rs:618、:648` 的旧注释指的就是它。
- Q4 写「没有在案 owner/退役规则」并归 C，查询词没有覆盖 unlink、ECONNREFUSED、清理、control-owner。ADR 取代了那两条注释，写了「产品从不 unlink 任何 socket」，第七节却没列这两个控制器，也没给去向。落地后仓内仍有一条核完身份再按名删除的路径，正是 :15 援引 #1823 否决的做法。它们 stop 后直接 start 的流程也会被第 9 条改变。
- 最小修法：考古把该先例列进 Q3/Q4（B 类），补换说法查询，写明否决依据（#1823 6994092216）。ADR 第七节列出两个控制器并给去向，二选一：把「不 unlink」限定为约束 Rust 域 bin 与 `production_session`，并写明这两个控制器按 0039:278 不是正式入口、不得用于本合同的端点目录；或把改为不删、停用交给 #1411 或 #2130。

**3. R8：探针与 X 实跑的原始输出不在证据分支（考古 Q4/Q8、MANIFEST:35–36、DEVIATIONS 2/3/5；ADR :72）**

## 分歧项的裁断

- **第 3 条不适用时回旧合同（:30）：降为非阻塞。** 三名分项审查者判 R5 BLOCK，复核者 3 比 3。我不同意拦。票面明写「分清既有方式与新方式的生效条件、旧调用者行为」「不动现有部署」。旧合同就是 main 现行行为：锁照持，有对象必拒，从不退役。我枚举了新旧合同来回切换的各条路，没有一条重新接纳残留或出现双写者，漏的只有上面第 1 处。审查者建议的「不合格一律拒绝」反而会让目录组可写的现有部署起不来。:30 的「系统不提供所需接口时才沿旧合同」与前句条件清单字面冲突，返修时改写成只管时序：认领开始前判定不适用走旧合同，开始后任何失败都拒绝。
- **缺 log 记在 R8，不另判 R1。** ADR 与草稿正文没有引用这两份 log。
- **端点目录在共享文件系统上：非阻塞。** 反例要两台主机各持本地库跑同一域，已越出 SPEC C09.1–2。建议补一行 statfs 本地白名单。

## 非阻塞项全文

1. 四.3（:30）不适用时回旧合同：不拦，但「系统不提供所需接口时才沿旧合同」与前句条件清单字面冲突，须改写成只管时序。另外空址而 owner 非我时，合格目录拒绝、不合格目录直绑，建议旧合同下见到 <basename>.owner 即拒。不要改成「不合格一律拒绝」，那会让端点目录组可写的现有部署起不来，违票面「不动现有部署」。

2. 四.4（:31）owner 用写入加截断原地更新，不是原子的。一次 kill -9 落在两个系统调用之间就留下半写 JSON，本域永久拒绝，只能等 #2130。建议定长编码单次等长写，或明写这是有意的活性代价，并加一臂强杀后的验收。

3. 四.1（:28）只要求锁持到监听 FD 关闭。应写成 guard 活过监听关闭、关库标记提交和数据库关闭三者，最后才释放，否则字面上允许短暂的双写者窗口。

4. 四.3（:30）没要求端点目录在本地文件系统；情形表「宿主重启」行（:78）的「合格持久卷」没有定义。建议补 statfs 本地白名单（同 store.rs 的 filesystem()），并写明重启后 st_dev 变了按身份不符拒绝。

5. 四.9（:51–53）标记只绑 writer_epoch。旧二进制同代服务被杀后前滚、或从正常关库后的备份恢复，旧标记都自洽有效。各补一行：回退前滚或恢复备份后须先正式恢复，或明写不在本合同保证内并交 #2130。

6. 四.12（:57）「launcher 不恢复、不升代」与 ADR 0039:285/:290、0038:60 的「launcher 换代、启动时恢复」，以及 ADR 0059 第 6 条不比较 s.socket 的理由句，字面上有出入。第七节应写明取代关系，并指明生产中正式 recover 由谁执行。

7. 四.3（:30）的 M 判定只对 S 做。带本地监听的 simulation X 的 socket 可能落在 S 的 M 内，新增的 owner 文件和改名会改动 M。建议把 M 判定扩到 X，或列为已知缺口并指定承接票。

8. 四.1、四.2（:28–29）「持锁即前代不再占有写者资格」比代码给的保证强：E/B/X 的 process_lock 不带 O_NOFOLLOW，也不复核锁文件身份，owner 只按路径字节比对 writer_lock。有 ECONNREFUSED 兜住活监听，安全不破。建议 owner 加记锁文件的 dev/ino，或写明 writer_lock 取哪种绝对化。

9. 验收（五）：认领表 vacant 两行、关停时标记提交失败非 0 退出都没有具名测试；:98「错 UID（在已有夹具权限能合法构造时）」是条件臂，不是二值；:44 与 :45 对试连非 ECONNREFUSED、身份不符该报哪种首错没写定；:61 endpoint-claim 行的序列化格式未定。

10. 六（:113）#1823 仍 open，ADR 0059:117 把残留处置交给了它；本裁定已给出处置，应写明 #1823 随本票关闭、改范围还是留有剩余交付。

11. 引用瑕疵：:104、:132 的 :994/:1105 是断言行，两个测试函数在 b7b79657 的 :934/:1068；考古 Q1 与 DEVIATIONS 第 1 项可补引已关票 #1895（ProcessLock 析构先显式解锁）作为「获得锁不证明前代 PID 已消失」的在案出处。
