   273	### 三、唯一正式 launcher 的 seam
   274	
   275	1. **身份**
   276	   - bin `production_session`，源文件 `rust/src/bin/production_session.rs`；
   277	   - Cargo feature `production_session`，含 `s_session` 与 X adapter 所需依赖，**不含** `backtest_bin` 和 `nautilus`；
   278	   - 全仓只有这一个 launcher。`theta_backtest`、`trading_system/live/runner.py`、`newchan` CLI、任何 `*_launcher.py` 都不是 launcher。
   279	2. **输入**
   280	   - 一份 manifest：已批准规则和政策版本、能力 manifest、原始输入来源、各域 DB 路径、时钟、adapter 选择（C10.1）；
   281	   - 一份 profile：ADR 0028 裁定一字段。
   282	   - `evidence_class` 只决定 adapter 装配：`simulation` 装受控撮合，`experiment` 和 `production` 装场所 adapter。三种运行环境只在 adapter 处分叉（ADR 0027:46）。
   283	3. **装配**
   284	   - 以独立 OS 进程启动 S、E、X、各 Bᵢ（C09.1）；每个域有自己的 `--db`、`.writer.lock`、`writer_epoch`。
   285	   - launcher 只负责启动、顺序、监督、换代和指纹计算。它不持任何域的写者身份，不产生交易意图。
   286	   - 生产部署中，域 bin 只能由 launcher 拉起。手工用生产库路径启动域 bin 的情形，是 TB-09 部署隔离（#1383/#1401）的验收对象，本 ADR 不把「约定」算作锁。
   287	4. **凭据**：launcher 从 profile 的 `credential_scope` 指向的来源读取凭据，**只**写进 X 子进程的启动环境。S、E、Bᵢ、查询壳和宿主 shell 环境都不含凭据（ADR 0028:36、C09.7）。
   288	5. **启动门**
   289	   - `production` profile 下，launcher 在启动时和失效触发后计算 TB-09 指纹，交给 X。
   290	   - X 把指纹连同 profile 版本持久化到自己的域库；指纹缺失或不符就拒绝发送，不回退旧 writer（ADR 0028:46、ADR 0030:44）。
   291	   - 启动时检测 checkpoint 并恢复（ADR 0038:60）。
   292	6. **换代**：先确认旧 X 和它的发送子进程已退出，再提升 `writer_epoch`、取得排他进程锁（C09.8）。旧 epoch 的写入被 `store.rs:466-467` 拒绝。

    95	1. **canon 定义**：解析符号链接后的绝对路径，路径最终条目是符号链接时也解析。路径尚不存在时，取最近存在祖先的 canon，再按原样接上剩余路径段。路径最终条目是悬空符号链接时，先取链接目标（相对目标按链接所在目录解析，多级链接逐级取），再对目标按本条求 canon。
    96	2. **S 测量边界**：
    97	   - `P = parent(canon(s.db))`，`b = basename(canon(s.db))`；
    98	   - `A = canon(parent(parent(s.admission_job_limits)))`；
    99	   - S 族条目：P 中名字等于 `b`，或以 `b.`、`b-` 开头的条目。
   100	
   101	   A 的推导不核验后缀，后缀合法性由 S 的 E1 核验（Q12 推荐答案）。
   102	3. **并发写域的库与判定目录**：库为 `economic.e.db`、每个 `economic.b[i].db`、`x.db`。对每个这样的库 `d` 取下列判定目录：
   103	   - `Q₁ = canon(parent(d))`，即 d 的目录项所在目录；
   104	   - `Q₂ = parent(canon(d))`，即 d 解析后实际库文件所在目录，也是 SQLite 侧件所在目录。d 不是符号链接时 `Q₁ == Q₂`；
   105	   - 锁目标目录 `Q₃ = parent(canon(L))`，对下列每个锁路径 L 各取一个：`L₂ = canon(d)` 接 `.writer.lock`，恒取；d 不存在时（跟随链接判存在，悬空链接算不存在）另取 `L₁ = Q₁/basename(d)` 接 `.writer.lock`。L 不是符号链接时 `Q₃` 等于 `Q₁` 或 `Q₂`；L 是符号链接（含悬空）时，`Q₃` 是其最终目标所在目录。
   106	
   107	   `L₂`、`L₁` 与 `process_lock` 的存在、不存在两个分支一一对应（`rust/src/session_transport.rs:43-63`）；d 不存在时两个分支都会被用到，见 Q2。
   108	
   109	   **并发写域的 socket 与判定目录**：读 `economic.manifest` 指向的经济 manifest，取 E 的 `e.socket`，以及对每个 `economic.b[i]` 取 `chong_id` 等于其 `chong` 的 `chongs[j].socket`。对每个这样的 socket 路径 `k` 取两个 socket 目录：`Q₄ = canon(parent(k))`，即 k 的目录项所在目录；`Q₅ = parent(canon(k))`，即按第 1 条解析最终链接（含悬空）后 bind 可能创建 socket 的目录。k 不是符号链接时 `Q₄ == Q₅`。两者都判，理由见 Q2 第四类。经济 manifest 读不出、缺这些字段或找不到对应 `chong_id` 时，同样在拉起前以 `InvalidDomain` 退出；E/B 的 `Config::load` 对同一文件本会确定性拒绝（`store.rs:158`、`:176`、`:286-287`），launcher 只是提前。
   110	4. **拒绝条件**：任一 `d` 的 `Q₁`、`Q₂` 或任一 `Q₃`，或任一 socket 的 `Q₄`、`Q₅`（下记 `Q`）满足下列任一条，即 `InvalidDomain`：
   111	   - `Q == P`；
   112	   - `Q == A`，或 `Q` 位于 `A` 之下；
   113	   - `Q` 等于某个 S 族条目的路径，或位于其下。
   114	
   115	   `d` 本身取了 P 内的 S 族名字，已被 `Q == P` 覆盖。S 侧原本也会以 `UnknownDatabaseSidecar` 确定性拒绝（`admission_provider.rs:229-243`），launcher 只是把判定提前。
   116	5. **不比较 launcher manifest `state_dir`**。理由是它只在 S init 之前写一次（`production_session.rs:320-323`），不与 S 打开窗口并发。
   117	6. **不比较 `s.socket`**。残留 socket 在 S 参数期就以 `TransportUnavailable` 确定性拒绝（`writer_cli.rs:357-359`），S 自己在 driver open 之后才 bind（`writer_cli.rs:725`、`:802`）。本条只管 `s.socket`；E/B 的 socket 按第 3、4 条判定。重启时谁来清理，归 #1823 调查，不在本裁定范围内。
   118	7. **不扩大范围**：P 的祖先目录、兄弟目录，以及 P 内既非族条目、也不在 A 内的子目录，都不在 M 内，一律放行。
   119	8. **错误信息**：stderr 必须含 `InvalidDomain`，并点名冲突的两条 manifest 字段及两侧 canon 路径。被冲突的字段按情形取：与 P 或族条目冲突时是 `s.db`，与 A 冲突时是 `s.admission_job_limits`。并发写域的字段名为 `economic.e.db`、`economic.b[<i>].db` 或 `x.db`，该侧路径给出命中的判定目录（`Q₁`、`Q₂` 或 `Q₃`）。socket 冲突时，并发写域一侧点名经济 manifest 的具体字段 `e.socket` 或 `chongs[<j>].socket`，该侧路径给出命中的 `Q₄` 或 `Q₅`。
   120	9. owner 落点：`load_manifest`（`rust/src/bin/production_session.rs:125`）。检查（含第 3 条读经济 manifest）位于其返回 `Ok` 之前，只读不写，因而早于 `check_existing_s`（`:300-302`）、任何 init、写 launcher `state_dir` 以及任何拉起。命中时不建任何域文件。
   121	10. **不设可调字段，不设放行开关**。依据是 ADR 0041:13 的判别句和 #799。launcher 判定和 S admission 核验判的是两件事：前者是静态布局，后者是打开窗口内的 stamp。两者不在同一个 if-else 上，也不互相兜底。
   122	11. **L-2 记录**：immutable 预检最多误拒、不会误放；改由 S 自核需要改 S v3 writer CLI，另行开票。本裁定不改实现。

     9	**一、适用范围。** 本通则只管**自由度**：正本标为 `[新缠论:选择]`、或属参数类且缠师原文无定论的量——构造选择、参数、档位、起点、阈值、场所 profile 等。缠师原文语义（`[旧缠论]`）与已裁教义推论（`[新缠论:推论]`）不是自由度，不变为可调：那是事实，不是偏好。一条量归哪类，以它所在正本的溯源标签为准；标签缺失时先补标签，再谈可调。
    10	
    11	**二、与 [#799](https://github.com/xy7365527-lang/NewChanlun/issues/799) 收敛通则的关系。** 可调 ＝ 事前在版本化记录里单选一个值，运行中全程只走这一个值。#799 禁两件事：同一个判断存在宽严两档实现，以及让宽松那档接管严格那档的失败（「严格版判不出 ⟹ 换宽松版再判 ⟹ 放行」）。本通则只覆盖不同的合法取值（参数值、构造选择、档位、起点、profile），同一判断的松紧两个版本不是自由度，事前单选也不得落为可调字段。在这个范围内两者不冲突。
    12	
    13	> **判别句**：先问候选是不是同一判断的两套松紧判据（两档实现；同一判据取不同参数值不算）——是 ⟹ #799 管辖，不是自由度，不得做成可调字段（哪怕事前单选）。不是 ⟹ 再看选值：发生在运行之前、写在版本化记录里、一次运行只读到一个值 ⟹ 合法的可调字段；运行中按前一个值的判定结果改走另一个值（同一 if-else 上的失败兜底）⟹ #799 违规，与是否「可配置」无关。
    14	
    15	推论：可调字段不得有「主值失败时的备用值」；要换值只能改签新版本、从头重推导。
    16	
    17	**三、落法。** 每个自由度落为：
    18	
    19	1. **版本化记录字段**——放进该量所属的具名版本化记录（签署记录、policy 记录或场所 profile），不另建配置面；
    20	2. **默认值**——每个字段必须有默认值，附推导依据（原文锚、ADR 或在案读数）；
    21	   **签署门字段的默认值 ＝ `AwaitingPolicy`**（用户 2026-10-20 批复 B-10，见 [#1586](https://github.com/xy7365527-lang/NewChanlun/issues/1586)）。凡已裁定「签署前不给值、不得代填」的字段——资金 cap（[ADR 0029](0029-common-cap-contention-policy.md) 裁定四）、量档与逐级容量（[ADR 0034](0034-quantity-tier-policy-growth-equity-shift.md) 的 `AwaitingPolicy{tier:d}`／`AwaitingPolicy{capacity}`）、成本门 θ 与成本输入（[ADR 0035](0035-cost-stop-policy-instance-and-base-extension-evidence.md)）、闸门后参数槽位（[ADR 0036](0036-operating-statistics-sampling-and-post-gate-parameter-protocol.md) 裁定九），以及其他已裁定由用户签署的风险阈值——运行时默认值就是 `AwaitingPolicy{<字段>}`：未签署则该字段所阻的动作不跑，不回退任何备用值。数值默认值只以「推荐值＋出处」写进版本记录，按「授权来源与生效边界」节取得适用授权后生效；真实资金与账户权限仍须用户确认。这样满足本条「每个字段有默认值」，也不违上述代填禁令；`AwaitingPolicy` 是等待签署的状态，不是第二个取值，因此不构成第二条所禁的备用值。
    22	3. **出处**——字段说明写明可选值集合、各值的来源与代价；
    23	4. **改签即新版本**——改值 ＝ 新版本，改后按新值重推导，不在旧版本内热改。
    24	
    25	实现不得把自由度写成代码常数（与 [ADR 0034](0034-quantity-tier-policy-growth-equity-shift.md) 被否方案「常数表 `depth_weights`」同向）。
    26	
    27	**四、合法候选保留，真错仍排除。** 裁决一个自由度时，被比较下去的候选分两种处置：
    39	## 授权来源与生效边界（#1909 / PR #1915，2026-11-07）
    40	
    41	用户本次明确要求「保留 DeepAgents 并去普通人工审批」，同时要求不误放真实交易、凭据权限。普通 P 类取舍、SPEC 实施授权、离线研究方法与不产生真实账户外效的参数选择，均以起草 + 非作者独审 PASS 由代理裁定；不再逐项等用户签署。PASS 必须绑定实际获审版本，不能复用正文变化后的旧 PASS。
    42	
    43	授权分两层，不能把文书裁定当成外部操作许可：
    44	
    45	- **代理裁定**：来源记为「代理独审裁定」，记录票号、作者、独审身份、获审版本、原件位置与生效域。它不是 `UserSigned`，不得填入只接受 `UserSigned` 的交易政策来源字段。普通开发/SPEC 走 #1909 合同，不以运行时资金记录能否消费为前置。
    46	- **独立资金与权限硬门**：真实资金投入/取出/改额、账户/场所激活、真实交易的量档与容量、成本/风险阈值，以及凭据和权限授予，仍须对应用户授权。代理可裁定方法、形成推荐值和实现方案；独审 PASS 不代签具体外部操作。只接受 `UserSigned` 的现有政策消费方保持原合同；缺授权仍 `AwaitingPolicy`，缺证据仍不启用。已授权值在原版本与有效域内使用不重复索要签署，扩大域或改值才重新取得对应授权。
    47	
    48	ADR 0029 的 cap、0034 的资金/容量来源、0035 的交易成本阈值与 0036 的真实账户阶段启用，适用上述独立硬门；普通研发选择适用代理裁定。历史用户批复、已签实例与其 `UserSigned` 来源不回写。新增代理裁定不能冒充这些历史签名，也不自动迁移到 production。

   131	
   132	（append-only：裁定一至四与验收清单原文不改，本节为现行修订。依据 #1539 P 类裁定稿，用户 2026-11-02 批复（[批复评论](https://github.com/xy7365527-lang/NewChanlun/issues/1539#issuecomment-6564138279)）；草稿、考古与审查原件：首两轮在 `/Volumes/AgentStorage/decisions/1539/`，其后依次为 `/Volumes/AgentStorage/fu17-repair40r/`、`/Volumes/AgentStorage/fu17-review40y/`、`/Volumes/AgentStorage/fu17-repair41f/`、`/Volumes/AgentStorage/fu17-review41k/`、`/Volumes/AgentStorage/fu17-publish41p/`（获批版本）；本仓存档 `.chanlun/review-results/issue1539-decision-20261102/`。）
