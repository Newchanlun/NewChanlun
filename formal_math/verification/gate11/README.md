只回答一个问题：给定提交（默认 `HEAD`）里的 `formal_math/sources/admit/` 与 `docs/chanlun/text/blog/`，是不是过审时的那一份。退出码 0 相符，1 不符，2 无法运行（含 git 对象读不到、`--rev` 无效、成功提示或钉选文本写不出去）。**只有 0 放行，任何非零都应阻断**；2 不表示材料没问题。`--print-pin` 只是打印规范钉选文本的辅助命令，不是放行命令。脚本自己写的提示与红行按 UTF-8 字节直接写出，不随 locale 变；`git` 自己的诊断原样透传到标准错误，`--print-pin` 的输出是原始字节（路径不保证是 UTF-8）。只认 `--root 路径`、`--rev 提交`、`--print-pin` 三个写法，不接受缩写，写错退 2。标准错误写不出时诊断丢失，退出码不变。除 Python 标准库外需要系统里有 `git`。`--root` 是检查脚本的参数，由调用方给定并受信任，脚本不鉴别它本身；自测按自身位置定位仓库，不接受这个参数。

- **准入材料**：用 `git ls-tree -r -t` 取该提交里这个目录下的全部条目（含目录节点）。文件条目必须是模式 `100644` 的普通文件；目录节点只许是文件路径实际需要的祖先目录，所以提交里记录的空子树也红。文件按「模式、内容 sha256、路径」逐行排成规范文本，须与**同一提交里** `admit_identity.pin` 的 git 对象逐字节相同（不读检出的钉选文件，检出时的换行转换不影响结果）。符号链接、可执行位、子模块、多一个或少一个受跟踪文件（不论放在哪个子目录）都红。钉选文件没有注释与空行的写法。
- **语料**：同样从该提交的 git 对象现算指纹，须等于脚本常量里的基线 `b6a35574…a0d`（与 `cd docs/chanlun/text/blog && sha256sum *.md | sha256sum` 同值）。目录里不许有子目录（含空子树）或非 `.md` 条目。
- **只读 git 对象，不读工作区。** 磁盘上的文件是否与提交一致不在本检查之内：CI 在新检出上运行，检出的就是被核的提交；换行转换、文件权限、未跟踪文件都不影响结果。读磁盘文件的下游工具若要这一层保证，须自己从 git 对象取内容，并且要绑定到同一个完整提交号、关闭替换引用（`GIT_NO_REPLACE_OBJECTS=1`）；普通的 `git cat-file` 在有替换引用时读到的可能不是被核的对象。
- 读 git 对象时关闭替换引用（`GIT_NO_REPLACE_OBJECTS=1`）。

**为什么只核身份。** 790 行、两遍原件重建零差分、作者文字摘要相符，这些性质在过审时已由非作者独立核实（#2316 评论 7166555103；#2317 两轮独审均确认入库表与 `2031547003` 逐字节一致）。内容相同则性质相同，这里不再重算，也就没有替身台账的问题。

**钉选了什么。** 49 项：`2031547003` 的 `fm09-admit/` 去掉 `errata/` 后的 46 个原件（逐字节相同）、改过标题与说明的 `candidate/README.md`、入库时新写的 `SHA256SUMS` 与 `CORPUS_FINGERPRINT`。复算：`python3 -I …/check_admit_identity.py --print-pin --rev <提交>`。

**不防什么。**
- 钉选文件、脚本常量与被钉内容在同一次改动里一起换，本检查不拦（自测 `table-and-pin-synced` 记录这一点）。改 `gate11/` 须经路径权限门与评审。
- 被比对的是内容的 sha256 与 git 模式，不含文件时间、属主等 git 不记录的属性。
- 运行环境由调用方负责：`GIT_DIR` 等环境变量、`--root` 与 `--rev` 应由 CI 工作流给定，不取自被审内容。脚本只固定了替换引用开关与 locale。
- 不核引文。`formal_math/` 里的硬证据引文目前没有过审的机检工具。

引文核对工具的输入只有一份（身份检查的输入见上节）：`formal_math/sources/admit/` 里的正文区准入表 `candidate/tier1_candidate.jsonl`（790 条，已过非作者实物审，范围仅限**正文归属**；记录见 #2316 评论 7166555103）。本目录不接入 `run_gates.py`，接入总入口等 #2312 过审后由主控做。

## 阻断检查

### 查什么

0. **身份钉选**（先查）：`pinned_admit.sha256` 钉着 `2031547003` 原 `SHA256SUMS` 去掉 `errata/` 后的 47 个入库原件各自的 sha256，其中 `candidate/README.md` 一项换成改后（标题加两处说明）的摘要。入库目录里每个文件须等于钉选值，目录里不得有钉选之外的文件（只允许新增的 `SHA256SUMS` 与 `CORPUS_FINGERPRINT`）。**这一步锁的是「过审的那一份」，不是「任一套自洽的」**：换 id、把剔除放回去、改处置理由、改合并脚本，哪怕同步重算了清单，都红。
1. **摘要清单**：`sources/admit/SHA256SUMS` 现算相符、无清单之外的文件；它与钉选清单对同一文件必须一致。它只是方便人查的副本，不是身份依据。
2. **行数与行结构**：恰 790 行；键序固定；id 不重复。
3. **逐行自洽**：区间在原行长度内、递增、不相交；`author_spans` 全在 `quote_spans` 内；`verdict` 与区间一致；按每条的 `lesson`、`line`、`author_spans` 从语料取字，复算 `author_text_sha256`。
4. **重建零差分**：在临时目录里用入库的 `merge.py` 从两遍原件重建，与入库准入表逐字节相同。
5. **语料指纹**：`docs/chanlun/text/blog/*.md` 的指纹（`sha256sum *.md | sha256sum`，文件名按字节序）等于基线 `b6a35574…a0d`，入库的 `CORPUS_FINGERPRINT` 也与基线一致。基线在脚本常量里。

### 信任前提与剩下的缺口

- **钉选清单与被钉文件若在同一次改动里一起换，本检查拦不住。** 钉选清单属门禁代码一侧，改它须经评审；这由路径权限（门 6b）和评审负责。自测里有一项显式记录这一点（只换处置理由并同步钉选，仍绿）。
- **重建用的是替身。** `merge.py` 写死了 `fm09-admit/…`、`fm09-register/tmp/lib.py`、`ledger_final.jsonl` 的相对布局，而登记册按票面不入库。脚本不改 `merge.py` 一字，在临时目录里搭出它要的布局：两遍原件、`adjudications.json`、`merge.py` 与语料从仓内拷入；`lib.py` 用 `merge_shim/lib.py`（只含 `BLOG` 与 `load()`，取文逻辑同正本）；`ledger_final.jsonl` 不可得，用甲遍原件的 id 序写一份只含 `id`、`who: 正文` 的替身。因此 `merge.py` 里「id 集合等于台账中 `who == 正文` 的 id」在仓内退化成「两遍 id 序相同」。替身只剩「重建能跑通」的作用，**身份由第 0 步的钉选保证**，不由替身保证；台账本身的核对只能回到 `evidence/2317-tier1-candidate` 上做。
- 替身返回的正文界标（`load` 的第二项）`merge.py` 不用，改它不影响结果，这符合重建合同（自测 `shim-same` 仍绿）；改行列表则红（`shim-different`）。

### 不查什么

不查摘句支持什么命题，不查标注者的判断对不对（那是非作者实物审的事），不查台账。`nonauthor_kind` 只是标注者分类，不是事实认定。

## 引文报告

### 读什么

扫 `formal_math/` 下 **git 跟踪的全部文本文件**（另含未跟踪但未被忽略的，不按后缀白名单；非 git 根目录回退为遍历，跳过 `.lake`、`.git`），抽出每条 `【归属 课号:行号】「…」`。

**显式排除清单**（报告里列出每项与被排除的文件数）：

| 路径前缀 | 理由 |
|---|---|
| `formal_math/sources/admit/` | 入库的准入材料原件：其中的 `【…】` 是标注规格与说明里的样例，不是被审引文，且须逐字节保留 |
| `formal_math/verification/gate11/fixtures/` | 自测夹具，故意含坏引文 |

非 UTF-8 文件与含 NUL 的文件列入报告的 `unscanned`，写明原因，不静默跳过。

**每条引文分开报四件事：**

1. `match`（字面匹配状态）与总 `status`。
2. `hits`：真正单独支持这串字的准入表 id，及命中的字符起止 `[起,止)`（行内 0 起、左闭右开）。**逐条匹配**：一条引文通过，当且仅当存在某一个 id、它的某一个作者区间完整包含这串字；同一课行多个 id 的区间**不**并起来用。
3. `outside_also`：同一串字在该行既出现在区间内又出现在区间外时为真，读数里注明「该行另有区间外出现」，使用者须自行确认指的是哪一处。
4. `attribution` 与 `attribution_accepted`：归属词封闭名单只收 **`缠师`** 与 **`原文`**。名单外的（`网友`、`正文`、`答疑`、`课间`、`解盘` 等）字面即使完全命中，`status` 也是 `attribution_not_accepted`，不算通过。仓内当前 `formal_math/` 没有这种标记；总计划手册里用过 `原文`，并大量用 `正文`/`答疑`/`课间`/`解盘`（那是分区标签，不是归属，故不收）。

**`match` 取值**（只有 `ok` 且归属在名单内才算通过）：

| 读数 | 含义 |
|---|---|
| `ok` | **整串原样、连续**命中，且完整落在某一个 id 的某一个作者区间内；不做任何归一（NBSP、全角空格、标点都按原字）。原文本身带省略号的，按整串原样命中处理 |
| `whitespace_differs` | 只差空白（含 NBSP、全角空格、各类空白）。供修稿，**不算通过** |
| `elided` | 引文带省略号（`……`、`…`、`...`、`。。。`），整串找不到；各片在同一个 id 的同一个作者区间内、按原文次序、位置不重用。**不算通过** |
| `elided_unsupported` | 带省略号但不满足上面条件（倒序、重用位置、各片分属不同区间或不同 id、有片找不到） |
| `spans_multiple_ids` | 这串字逐字在原行里，字都被准入，但没有任何单个 id 的单个区间完整包含它（跨 id 才凑得齐）。**不算通过** |
| `quote_overlaps_excluded_text` | 逐字在原行里，但含未准入的字（被剔除的，如 017:40 的「“一分为二”」，或不在任何作者区间） |
| `quote_spliced_across_spans` | 原行里找不到，但等于把某 id（或各 id）的作者区间文字拼起来再摘（裁剪条目跨段拼成一句） |
| `quote_not_in_line` | 原行里逐字找不到 |
| `lesson_line_not_in_table` | 表外课行 |
| `empty_quote` | 引号内为空 |

只有 `【缠师/原文 …】「…」` 这种硬证据括号归引文核对管；`『…』`（网友或编者文字）与 `〈…〉`（概括）不抽。

### 标记解析（形似但不合规的标记进未解析，写原因）

合规标记是：归属词（不含空白、数字、冒号）+ **至少一个空白** + **三位**课号 + ASCII 冒号 + 行号，且 `】` 之后（可隔空白）同行紧跟 `「…」`。凡 `【…】` 里出现「数字、冒号、数字」而不合规的，一律进 `unparsed_markers` 并写原因，**不会被悄悄读成另一课，也不会静默丢掉**：课号不是三位（如 4 位或 2 位）、全角冒号、归属词与课号之间无分隔、课行之后还有多行号写法（`、27` 之类）、缺归属词、没有同行的 `「…」`（跨行、嵌套引号，或用了 `『…』`）。报告给出这些标记的文件、行、列与原因。

### 已知局限（抽取靠模式匹配）

- **跨行引文**：`「` 与 `」` 不在同一物理行，抽不到，只进未解析。
- **嵌套引号**：引文内部再含 `「` 或 `」`，不抽，只进未解析。
- **一行多条**：能抽，每条各自读数。
- **多行号写法**：不当作引文，只进未解析。
- 不理解 Lean 注释前缀、Markdown 代码块或表格；标记与 `「` 之间只许隔空白。
- 只看课行：引的是邻行的字，报 `quote_not_in_line`，不会替你找邻行。
- 一个标记里若恰含「数字:数字」但本意不是引文（如时间），会进未解析，属宁多勿漏。
- 对当前 `formal_math/` 实跑，硬证据引文为 0 条；这个 0 不说明抽取器已被真实样本检验，检验靠 `selftest.py` 的夹具。

升为阻断的条件：经非作者独审后另行裁定（#2317 票面）。

## 自测

`selftest.py` 在临时目录里拷一份准入表、语料与门禁代码，逐项改坏再跑，断言指向被测样本：

- **B2 身份钉选**：独审的 18 种改动模式，名字与报告一致（`swap-id`、`swap-one`、`drop-id`、`add-id`、`restore-votes`、`no-cut`、`no-cut-synced`、`cut-bad`、`cut-reason`、`corpus-only`、`corpus`、`spec-stale`、`spec-refresh`、`merge-stale`、`merge-refresh`、`merge-different`、`shim-different`、`shim-same`），每项断言退出码与诊断里的文件或 id；只有 `shim-same` 应绿。
- **钉选以下各层**：把钉选清单同步换掉后，作者文字摘要与重建差分各自点到被改的 id（分别断言）；只翻 `passes_agree` 时只有重建差分红；删一行红；缺整个 admit 目录与「目录在、缺准入表文件」分别走各自分支。
- **引文报告夹具** `fixtures/cites.md`：每行带 `case:`（独审模式名）、`expect:`（逐条应得读数）、`ids:`、`outside:` 或 `unparsed:`（该行、该列应有一条未解析且原因含该子串），并校验引文总数与未解析总数等于标注之和。
- **扫描范围**：`.txt` 与 `.lean` 里的引文被扫到；admit 目录被排除并计数；非 UTF-8 与二进制文件进未扫描清单；门禁自己的 README 与脚本不产生噪音。
- **反向检验**：弱化夹具（去掉跨行样例、改错未解析原因）、弱化改坏动作（把「放回被剔除的字」换成只翻 `passes_agree`）、弱化被测的钉选比对，自测都必须变红。
