## 一、`U-1a`：等值分型的破平方向（见证 `W7a`）

### 1.1 裁定

1. **默认破平方向取较早端点**（`PenTiePolicy.preferEarlier`）。
2. **破平策略保留为解析函数的独立可选参数**，位置与现稿相同（`penPivots`、`parsePens`、`penOnlineState` 的第三个参数，默认 `.preferEarlier`）。**不并入 `PenRule`**：接口约束页把 `PenRule` 定为三个字段，对撞报告第 14 项已判 `EQUIV`，没有理由为一个平局约定去动它。
3. `preferLater` 只作审计对照臂。主线基底 `segmentBase` 不暴露该参数，保持现状。
4. 现稿的等值簇延迟破平机制合规，判据见 1.3。需要纠正的只有一句文档串（见 1.5）。

### 1.2 论证

- **硬证据**：`077:54`、`077:42`、`069:26`、`065:30`。
- **背景旁证**：无。

第一，原文对等值只说到先保留为止：`077:54`「不满足上面情况的，例如相等的，都可以先保留。」之后由谁胜出，原文没有写。所以这是一条必须由主线补上的约定，不是对原文的解释。

第二，默认方向应与主线的反证判据同源。`077:42`「一个底不经过一个顶后就有一个更低的底，这是最典型的笔没完成的情况。」推翻前一个底的条件是出现**更低**的底。等值的后底不满足这个条件，所以前底没有被推翻，应当留下。第二节裁定的解析核只在严格更优时回溯，默认取早与它是同一条判据；若默认取晚，就等于让一个不构成反证的等值分型改写已有端点。（`077:44` 的不等号有笔误，按包内 B-42 不带入主线，本文不以它为据。）

第三，取早让已经给出的笔端点不因等值而移动。有限例 F7（11 根）：

`Z[39, 40, 39, 38, 37, 0, 1, 16, 15, 0, 1]`，局部分型 `T@1(43)`、`B@5(0)`、`T@7(19)`、`B@9(0)`。

读到第 7 根时两种策略都给出一笔 `T@1(43) → B@5(0)`。读到第 11 根，等值的 `B@9(0)` 出现：取早仍是 `T@1(43) → B@5(0)`；取晚把这一笔的终点挪到 `B@9(0)`。价格没有创新低，一支已成的笔却换了终点。按 `069:26`「分型可修改，证明图形没完成。」取晚等于宣布该图形未完成，而唯一的依据是一次平局。取早则满足 `065:30`「当下的分析和事后的分析，是一样的」在这一点上的要求。

第四，全包的平局约定应当一致。M10 的 `mergePair` 对并列极值下标取较早者（`Kline.lean` 第 45、46、50、51 行），M14 的 `directPivots` 等值留早（`Instance.lean` 第 59 行）。M12 取早与它们同向。

`W7a` 的结果：取早输出 `B@1(0) → T@9(14)`，取晚输出 `B@5(0) → T@9(14)`，两者都满足 S 与 S⁺。主线取前者。

### 1.3 现稿等值机制的核验

核验对象是 `Pen.lean` 第 109 至 240 行（`PenTiePolicy`、`PenPivotCluster`、`penPivots` 及其局部函数）。

| 项目 | 结论 | 依据 |

| 在线核是否依赖破平策略 | 不依赖。`stepPivots`、`rewindPivots`、`linkPivot` 都不接收 `tie` | 读码，第 152 至 193 行 |

| `OrderDual` 对称性 | 成立。对偶只换顶底与大小，不换先后，所以取早对偶后仍是取早 | 同上，P4 零反例 |

结论：R3 的延迟破平没有 R1 的两类吞笔缺陷，两种策略各自给出合法分解，对偶对称。

### 1.4 一条必须写明的限制：破平可以改变笔数

现稿第 109 行的文档串说等值候选只有在能接上同一组邻点时才按先后破平。这句话描述的是单步替换，容易被读成两种策略的输出只差在等值端点的选择上。这个推论不成立。有限例 F4（12 根）：

`Z[1, 0, 8, 0, 1, 8, 0, 1, 2, 3, 8, 7]`，局部分型 `B@1(0)`、`T@2(11)`、`B@3(0)`、`T@5(11)`、`B@6(0)`、`T@10(11)`。

- 取早输出 `B@1(0) → T@5(11)`，一笔。
- 取晚输出 `T@2(11) → B@6(0) → T@10(11)`，两笔。

原因是一次等值替换之后，新的链端可能多出一条延伸边。73,284 例的抽查里有 728 例两种策略给出的极值序列不同。这不是缺陷，取早本来就意味着保留先到的那一个；但文档串必须写明这一点，下游不得假设笔数与破平策略无关。

## 二、`U-1b`：声明式不唯一之下的主线解析（见证 `W7b`、`W7c`）

### 2.1 裁定

1. **主线确定性解析取“在线从左至右、保首极值、严格反证多步回溯”**。全局最多笔数优先被否决。
2. **规则正文**（R3 的 `stepPivots`、`rewindPivots`、`linkPivot`、`penRepair` 即此规则，逐条对应见 2.4）：
   - **K1 栈与帧**：栈中每一帧是一个等值簇；相邻两帧异性，且前帧某成员与后帧成员之间有边。
   - **K2 起始**：第一个局部分型入栈，成为栈底。
   - **K3 新分型与栈顶同性**：等值且能接上栈顶的前驱帧（或栈只有一帧）则入簇，接不上则丢弃；严格更优则从栈顶起做反证回溯（K5）；更劣则丢弃。
   - **K4 新分型与栈顶异性**：能与簇内任一成员成笔则压栈；否则从次顶（与新分型同性的那一帧）起做反证回溯（K5）。
   - **K5 反证回溯**：设当前考察的同性帧为 `p`。新分型 `x` 必须**严格优于** `p`，否则放弃、栈不变。`x` 严格优于 `p` 时，若 `p` 是栈底或 `x` 能接上 `p` 的前驱帧，则弹出 `p` 及其上各帧，`x` 入栈；若接不上，则越过那一帧，对再往前的同性帧重复。越到栈底只剩一个接不上的异性帧时，放弃、栈不变。
   - **K6 收尾修补**：对在线链反复做三种修补直到不动点。链端延伸（允许把链端换成能接上另一侧邻点的等值替身）；同邻替换（候选严格更优，或等值且按破平策略占先，并同时接通前后邻点）；两点细分。
3. **“保首极值”的准确含义**是下面三条不变量，而不是保留时间上的第一个分型：
   - **INV-P1**：栈底帧的性质恒等于首极性。
   - **INV-P2**：栈底只会被同性质且严格更优的分型替换。
   - **INV-P3**：输出链恒含一个首极性的全局最优极值（等值亦可）。首极性是底，链里就有历史最低底；首极性是顶，链里就有历史最高顶。
4. **`077:40` 的唯一性宣称的归位**：
   - 字面全称命题（凡满足条件的划分只有一种）在 S 与 S⁺ 下都是假的，归 `Chan/Audit/Literal`，见证是 `W7c`，另有同首端仍不唯一的 F6。
   - 主线保留两条命题。其一，`parsePens` 是函数，输出满足 S⁺（这是 2.4 的 INV-1）。其二，**条件唯一性**：若全部相邻的局部分型两两成笔，则满足 S 的分解恰有一个，就是全部局部分型（2.3 的 T-U1-2）。
5. **现稿是否相符**：解析核与本规则相符，未发现新的违例。另登记四类由本规则带来的边界现象（2.5），其中没有一类需要改解析核。

### 2.2 论证

- **硬证据**：`069:20`、`077:54`、`077:42`、`077:38`、`065:38`、`065:40`、`062:26`、`077:40`、`069:26`、`078:24`、`079:58`。
- **背景旁证**：`[二级旁证 081:110]`、`[二级旁证 099:56]` 只说明笔规则参数的来历，`[二级旁证 078:206]` 只说明原作者在线段上承认划分依赖起点；三者都不用于下面的推理。

**（一）不唯一是事实，必须由解析函数取值。** `065:40`「所有的图形，都可以唯一地分解为上下交替的笔的连接。」与 `077:40`「这样可以唯一确定出笔的划分」是原文的宣称。`W7c` 的 13 根序列有两个都满足 S 的分解 `B@1(0), T@11(20)` 与 `T@3(15), B@7(5), T@11(20)`，本工位用脚本复核无误，两者也都满足 S⁺。25,866 例的穷举里，满足 S 的分解恰有一个的只有 1,508 例，满足 S⁺ 的分解恰有一个的有 10,110 例。唯一性不可能靠收紧合法性条件得到，只能靠确定性规则。

**（二）`077:40` 的证明缺口在哪里。** 原文的论证从两个划分第一处不同的那一笔入手，并写明 `077:40`「这个的N可以等于1，这样就是从一开始就不同」。但随后的推理用到了前一笔终点对两个划分相同这个前提，`N` 等于 1 时没有前一笔，这一步落空。`W7c` 的两个分解正是从第一笔就不同。更进一步，首端相同也不够。有限例 F6（12 根）：

`Z[1, 0, 1, 2, 3, 8, 7, 6, 5, 0, 16, 15]`，局部分型 `B@1(0)`、`T@5(11)`、`B@9(0)`、`T@10(19)`。

`B@1(0), T@5(11), B@9(0)` 与 `B@1(0), T@10(19)` 都满足 S⁺，首端相同。原文论证里 `077:40`「在这两个底之间不可能还存在一个顶」那一步默认两种划分保留的分型集合相同，这里不成立：`T@10(19)` 离 `B@9(0)` 太近，一种划分保留 `B@9`，另一种保留 `T@10`。这就是 `069:20` 的二选一。

**（三）二选一时原文选哪一个。** `069:20` 给出了唯一的一个判例，结论是 `069:20`「只能取第二个绿箭头」，即取后到的那个顶，放弃夹在中间的底，先前的顶也不再算笔中的顶。判例里两个底分型连续时前一个不算，用的是 `065:38` 的规则。判例没有写两个顶孰高（配图不在包内）；主线把后顶严格更高作为触发条件，是按下面第（四）点补上的。`W7b` 是这个判例的整数化：`T@1(20)`、`B@5(10)`、`T@7(25)`、`B@11(12)`，`T@7` 离 `B@5` 太近。主线输出 `T@7(25) → B@11(12)`，与判例一致。全局最多笔数优先在这里有两条等长的链，靠末端极值比较选了 `T@1(20) → B@5(10)`（对撞报告 `W7b` 所记乙方行为），把历史最高顶留在笔外，与判例相反。

**（四）回溯为什么必须以严格更优为条件。** `077:54` 规定同性质分型顶留高、底留低，`077:42` 把后底更低定为前一划分错误的标志。两处都是严格比较。所以新分型只有严格压过某个已保留的同性帧，才构成对它的反证；等值或更弱的新分型不构成反证，不得改写历史。R1 的缺陷是回溯时不比较就弹栈；R2 的缺陷是让等值也能弹栈。两者都违反这一条。

**（五）为什么回溯可以是多步的。** 新高 `x` 压过上一个保留顶 `p` 之后，要接到 `p` 之前的底上。若接不上，在不带不相交开关的规则下原因只能是中间出现了比那个底更低的底，于是那个底本身也不再是其后一段的最低点，按 `077:42` 它所在的那一笔没有完成。继续向前，直到找到一个能接上的底，把中间各笔并成一笔。这正是 `062:26`「所谓笔，就是顶和底之间的其他波动，都可以忽略不算」的用法。`069:26` 说完成的图形不可修改、可修改即未完成；这句话对规则没有额外约束，它只是把“会被 K5 改写的那些笔”定义为未完成。

**（六）为什么 K5 的最后一句不能删。** K5 规定越到栈底只剩一个接不上的异性帧时放弃。这句话看上去随意，把它删掉、改成此时一律以 `x` 重启全栈，规则会更整齐。本工位试过这个变体，它是错的。有限例 F5（23 根）：

`Z[17, 16, 17, 18, 19, 32, 31, 8, 9, 10, 11, 16, 15, 14, 13, 0, 1, 24, 23, 22, 21, 8, 9]`，局部分型 `B@1(16)`、`T@5(35)`、`B@7(8)`、`T@11(19)`、`B@15(0)`、`T@17(27)`、`B@21(8)`。

变体输出 `T@17(27) → B@21(8)`。但 `T@5(35) → B@15(0)` 是一支合法的笔，它的顶比链里所有的顶都高，底比链里所有的底都低。变体丢掉了一支在两端都严格压过自己的笔，直接违反 `077:54` 的顶留高、底留低。R3 在这里输出 `B@7(8), T@11(19), B@15(0)`，保住了历史最低底。原因是栈会遗忘：`T@5(35)` 早先已被一次回溯连带弹出，变体重启时只同栈里剩下的顶比较，比不到它。R3 的那句限制让栈底的性质永不改变，从而保证 INV-P3，也就保证不会出现这种两端被压过的链。4 万例随机抽查里，变体有 4 例违反 S⁺、176 例违反 INV-P3；R3 两项都是零。

**（七）否决全局最多笔数优先的四条理由。**

1. 与 `069:20` 的判例相反（见（三））。
2. 会选出被历史笔两端压过的链。有限例 F2（32 根）：

   `Z[55, 56, 55, 54, 53, 16, 17, 18, 19, 32, 31, 30, 29, 8, 48, 47, 46, 45, 24, 25, 26, 27, 40, 39, 38, 37, 24, 25, 26, 27, 40, 39]`

   满足 S 的分解恰有两个：历史链 `T@1(59), B@5(16), T@9(35), B@13(8)`（三笔）与后段链 `T@14(51), B@18(24), T@22(43), B@26(24), T@30(43)`（四笔）。笔数优先取后者。但 `T@1(59) → B@13(8)` 是合法的笔，顶高于后段链所有的顶，底低于后段链所有的底。S⁺ 拒绝后段链。
3. 本身仍不唯一。等长的链需要再加一层平局规则，`W7b` 里出问题的正是这一层。

### 2.3 条件唯一性（T-U1-2）

**命题**。设笔规则的 `requireDisjointFractal` 为假，无包含序列的全部局部分型按位置为 `v_1, …, v_n`，且对每个 `i` 有 `E(v_i, v_{i+1})`。则满足 S 的分解恰有一个，即 `v_1, …, v_n`；它也满足 S⁺。

**证明概要**（未经 Lean 内核）。此时边等价于间距条件加极值包络条件，间距条件对更远的一对分型自动成立。

1. 首端必为 `v_1`：否则首端 `v_i` 满足 `E(v_{i-1}, v_i)`，可向前延伸，不饱和。尾端同理必为 `v_n`。
2. 链中相邻两项必在全体分型中相邻。设相邻两项为 `a = v_i`、`b = v_j`，`j ≥ i+3`，不妨设 `a` 为底。取 `x` 为其间极值最高的顶，取 `y` 为 `x` 之后、`b` 之前极值最低的底（`v_{j-1}` 是底，所以存在）。由 `E(a,b)` 的包络与 `x`、`y` 的取法，逐项验证得 `E(a,x)`、`E(x,y)`、`E(y,b)`，于是可细分，不饱和。
3. 全体分型构成的链满足 S：两端外没有分型；能替换 `v_i` 且接通两邻的同性分型只能位于两邻之间，只有 `v_i` 自己；相邻两项之间没有分型可供细分。S⁺ 新增的两项同样成立：等值替身必须接通邻点，仍只有自己；任何一支笔的两个端点都在链里，不可能严格压过链。

**数值核验**。25,866 例穷举中满足前提的有 302 例，302 例的 S 分解与 S⁺ 分解都恰为全体局部分型。带不相交开关的规则未核验，不在命题范围内。

这条命题就是 `077:40` 在主线里能够成立的形态：相邻分型都够得上成笔时，划分唯一；一旦出现 `069:20` 那样相邻顶底成不了笔的情形，唯一性就要靠 2.1 的规则。

## 三、`O-1`：声明式谓词 `ValidPenDecomp` 的强化

### 3.1 裁定

1. **需要强化**。现稿的 `penChoicesSaturated` 有两个真实的漏洞，各补一处。
2. **强化一（等值替身）**：链端的可延伸检查，从“链端自己能否再接一笔”改为“链端或它的任一等值替身（替身须接得上链端另一侧的邻点）能否再接一笔”。
3. **强化二（不被压过）**：新增一项。图中不得存在这样一支笔，它的两个端点各自严格优于链内全部同性质的端点。
4. 强化后的谓词记作 S⁺，等于现稿四项加第 3 条，其中饱和项按第 2 条修改。
5. **不能再强**。“首端之前的弃笔必须被首端压过”“弱压过也不允许”这两种更强的写法，都会拒绝 R3 自己的合法输出（3.5）。`badRewind*` 那一类截断后缀因此有一部分在声明层面是合法的，只在解析层面被排除（3.5）。

### 3.2 精确定义与 Lean 草案

设 `V` 为全部局部分型，`xs` 为候选链。

- **等值替身**：`x` 是 `a` 的等值替身，指 `x ∈ V`，与 `a` 同性质且极值相等。`a` 是自己的替身。
- **可延伸（修订）**：对链首 `a`（后邻为 `n`，可缺），存在 `a` 的替身 `x` 使 `E(x,n)`（`n` 缺则免），且存在 `y ∈ V` 使 `E(y,x)`。对链尾对称。
- **被压过**：存在 `u, v ∈ V` 使 `E(u,v)`，且对 `xs` 中每个与 `u` 同性质的 `c`，`u` 严格优于 `c`；对 `v` 同样。某种性质在 `xs` 中不出现时，对应条件空真。

```lean
def penChoicesSaturated (r : PenRule) (bars : List (MergedBar P)) (allPivots : List (LocalFractal P))
    (prior : Option (LocalFractal P)) : List (LocalFractal P) → Bool
  | [] => true
  | a :: rest =>
    let edge := fun x y => decide (ValidPenPair r bars x y)
    let next := rest.head?
    let twin := fun (x : LocalFractal P) => x.kind = a.kind && x.extreme = a.extreme
    let canExtend :=
      (prior.isNone && allPivots.any fun x =>
        twin x && next.all (edge x ·) && allPivots.any (edge · x)) ||
      (next.isNone && allPivots.any fun x =>
        twin x && prior.all (edge · x) && allPivots.any (edge x ·))
    -- dominated 与 subdivides 两项照现稿第 66 至 71 行，不改
    !canExtend && !dominated && !subdivides && penChoicesSaturated r bars allPivots (some a) rest

/-- 图中没有一支两端各自严格压过链内全部同性端点的笔。 -/
def penChainUndominated (r : PenRule) (bars : List (MergedBar P))
    (allPivots xs : List (LocalFractal P)) : Bool :=
  let edge := fun x y => decide (ValidPenPair r bars x y)
  let beats := fun (x : LocalFractal P) => xs.all fun c =>
    c.kind ≠ x.kind || (if c.kind = .top then c.extreme < x.extreme else x.extreme < c.extreme)
  !(allPivots.any fun u => allPivots.any fun v => edge u v && beats u && beats v)

abbrev ValidPenDecomp (r : PenRule) (bars : List (MergedBar P)) (xs : List (LocalFractal P)) : Prop :=
  xs.Sublist (scanLocalFractals bars) ∧ xs.IsChain (ValidPenPair r bars) ∧
  (xs.isEmpty = true → (scanLocalFractals bars).isEmpty = true) ∧
  penChoicesSaturated r bars (scanLocalFractals bars) none xs = true ∧
  penChainUndominated r bars (scanLocalFractals bars) xs = true
```

草案沿用现稿的写法（命题到布尔的自动转换、`List.any`、`Option.all`），签名不变，`ValidPenDecomp` 多一个合取项，仍可判定。草案没有编译过，落地时以 `lake build --wfail` 为准。两条文档串的硬证据建议用 `077:54`（强化一：等值先保留；强化二：顶留高、底留低）与 `062:26`。

### 3.3 论证

- **硬证据**：`077:54`、`077:42`、`062:26`、`069:16`、`077:38`。
- **背景旁证**：无。

**强化一的理由。** `077:54` 让等值分型都先保留，声明层面等值的两个分型地位相同。现稿只问链端自己能不能延伸，于是把一个接不上任何笔的分型单独留下也算饱和，哪怕它的等值替身明明能成笔。`tieDropEarlier*` 就是这样：`Z[1, 0, 8, 7, 6, 5, 0, 1]` 里 `B@1(0)` 与 `B@6(0)` 等值，`T@2(11) → B@6(0)` 是合法的笔；现稿接受零笔孤点 `B@1(0)`，因为 `B@6` 不是严格更优，支配检查不触发，而 `B@1` 自己又确实没有边。修订后 `B@6` 作为替身可向前接 `T@2`，孤点被拒绝。R3 的解析器在修补步早已这样做（`Pen.lean` 第 205 至 212 行），谓词只是没跟上。

**强化二的理由。** 一条链若被某支笔在顶和底两端同时严格压过，那么保留这条链就同时违反了 `077:54` 的顶留高与底留低，而且没有任何一端可以作为补偿。`069:16` 与 `077:38` 给出的是单笔的规范，管不到一条链与链外各笔的关系。现稿的三项检查也都是局部的：延伸只看链端的直接邻接，支配要求更优者接通链内两邻，细分只看相邻两项之间。一条与历史不相连的后缀链，三项都查不到它。F2 里 R1 输出的四笔后段链就是这样通过 S 的，而历史上的 `T@1(59) → B@13(8)` 在两端都压过它。S⁺ 拒绝它。

**两项为什么都只在“严格”与“等值”的边界上动手。** 因为谓词必须对破平中立。现稿文档串写明等值不排斥任一解，主线的两种破平策略都必须产出合法分解。强化一只扩大了“谁可以代表链端去延伸”，强化二要求两端都严格。两者都不会在等值的两个解之间偏袒任何一个。

### 3.5 为什么不能再强

R1 审阅希望声明式谓词拒绝 `badRewind` 的那条截断后缀。对本文重构的 `badRewind*`，这做不到，理由有三条，每条都有 R3 自己的输出作证。

**第一，同一类型的链就是 R3 的合法输出。** `badRewind*`（F3a）里被质疑的链是 `T@10(51), B@14(24)`：它弃掉了首端之前首尾相接的两支笔，自己的首端是历史最高顶，被弃各笔的顶都低于它。F3b 里 R3 输出的正是 `T@14(51), B@18(24)`：弃掉首端之前首尾相接的三支笔，首端是历史最高顶，被弃各笔的顶都低于它。两条链与图的关系同型，区别只在 F3b 最前面多一个顶。要拒绝前者而放过后者，条件就得看首极性。而把首极性写进合法性谓词，会拒绝 `W7c` 的第二个分解（它弃掉了首极性的全局最低底），与兼容 `W7c` 双饱和的要求冲突。本工位没有找到不看首极性而能区分这两者的条件；试过的两种更强写法见下面两条，都被 R3 自己的输出证伪。

**第二，“首端之前的弃笔必须被首端压过”不成立。** 即要求首端之前每支弃笔的同性端点都不严格优于首端。带不相交开关时 R3 违反它。有限例 F10（27 根，规则 `⟨3, 3, true⟩`）：

`Z[17, 16, 17, 18, 19, 24, 23, 22, 21, 16, 17, 18, 19, 32, 0, 1, 56, 0, 1, 8, 7, 6, 5, 0, 1, 32, 31]`

R3 输出 `T@19(11), B@23(0)`，而首端之前的弃笔 `B@1(16) → T@5(27)` 的顶高于 11。这个输出是合理的：历史最低底 0 把此前的底全部压过，链在最低底重启，修补步再向前接上 `T@19`。把同样的要求也加在尾端一侧，6 万例里首尾合计有 5 例违例，全部出现在带不相交开关的规则下。

**第三，弱压过也不能禁。** 即把强化二放宽成“两端都不劣、且至少一端严格更优”。R3 在 `oldPenRule` 下就违反它。有限例 F9（10 根）：

`Z[1, 0, 16, 0, 1, 2, 3, 8, 0, 1]`，分型 `B@1(0)`、`T@2(19)`、`B@3(0)`、`T@7(11)`、`B@8(0)`。

R3 输出 `B@3(0) → T@7(11)`，而 `T@2(19) → B@8(0)` 的底与之等值、顶严格更高。104,180 例里这种情形在取早策略下有 1,956 例。它与 `equalRewindDestroy*` 里 R2 的输出是同一类型，所以 S⁺ 也拒绝不了后者。

**结论。** 声明层面能拒绝、且不误伤解析器的，就是 3.1 的两项。`badRewind*` 与等值回溯那两类截断后缀，都没有被任何一支弃笔在两端同时严格压过（前者的首端是历史最高顶，后者与弃笔在一端等值），声明上是合法分解，只是不是主线的取值。把它们挡在外面的是解析核的 K5 与不变量 INV-P1 至 INV-P3。这三条不变量应当作为关于 `parsePens` 的定理去证，而不是塞进合法性谓词。R1 至 R3 的回归锁因此应分两层：谓词层锁 3.4 表里前三行，解析层锁其余各行。

## 四、`U-2`：`penOnlineState`（见证 `W8a`、`W8b`）

### 4.1 裁定

**`U-2a`**：没有保留分型时返回 `none`，类型保持 `Option PenOnlineState`。不借 `InitIncludePolicy` 返回总函数。

**`U-2b`**：设 `xs` 是 `penPivots` 的输出，`f` 是其末项（尾端分型），`after` 是 `f` 的中心之后的全部 K 线（至少含 `f` 的右邻）。记 `ahead` 为自 `f` 起的新笔方向（`f` 为底则向上），`back` 为其反向，即以 `f` 为终点的前一笔的方向。

1. **尾端是否被突破**：`after` 中存在一根 K 线，沿 `back` 方向严格越过 `f` 的极值（`f` 为顶时有更高的高点，`f` 为底时有更低的低点）。
2. **方向**：未被突破取 `ahead`；已被突破取 `back`。
3. **阶段**：末根 K 线沿所取方向严格越过 `after` 中此前每一根 K 线的同向极值，则为“确认延伸为笔中”（阶段 1）；否则为“分型构造中”（阶段 0）。`after` 只有一根时为阶段 1。
4. 等值不算越过：与分叉 4 的严格突破口径一致。

四态之间的切换因此是：

| 当前 | 事件 | 之后 |
|---|---|---|
| （d, 1） | 末根未创新极值 | （d, 0） |
| （d, 0） | 末根重新创出新极值 | （d, 1） |
| （d, 任意） | 反向分型被 `parsePens` 保留为新尾端 | （d 的反向, 1） |
| （d, 任意） | 后续 K 线突破尾端分型自身的极值 | （d 的反向, 1），即前一笔恢复延伸 |

### 4.2 论证

- **硬证据**：`091:28`、`091:30`、`081:68`、`080:28`、`077:42`、`108:18`、`079:86`。
- **背景旁证**：无。

**`U-2a`。** `091:28`「走势必然落在一确定的具有明确方向的笔当中」的前提是有笔。笔的端点必须是分型：`081:68`「没有顶分型，没有顶；反之，没有底分型，没有底。」`080:28` 同义。没有分型就没有端点，也就没有笔，方向无从谈起。所以笔定理的字面全称（任何的当下）在第一个局部分型出现之前不成立，应作为字面命题归 `Chan/Audit/Literal`；主线的可证形态是：状态为 `none` 当且仅当保留分型为空，当且仅当局部分型为空。

借 `InitIncludePolicy` 补出方向有两个问题。其一，那个参数裁的是开头即包含时的合并方向，是 M10 的判定；拿它来答 M12 的当前笔方向，是用一个判定的输入去冒充另一个判定的结论。其二，按对撞报告 `W8a` 所记，乙方对两根上升 K 线配向上策略给出（向上，分型构造中），阶段也是错的：此时没有任何分型在构造。

**`U-2b` 的阶段判据。** `091:30`「0代表分型构造中，1代表分型确认延伸为笔的过程中」。阶段 1 说的是起点分型已确认、走势正沿笔的方向延伸；阶段 0 说的是可能终结这一笔的反向分型正在构造、尚未确认。`079:86` 写明顶分型之后不一定成笔，所以一个反向分型出现之后有两种去向：被新的极值否决，回到阶段 1；或被确认为笔的端点，方向翻转。确认在主线里就是被 `parsePens` 保留。

于是阶段 0 等价于：尾端之后存在一个尚未被否决的反向局部分型。在无包含序列上，这又等价于末根 K 线没有创出尾端以来的严格新极值（若末根不是新极值，取得极值的那一根就是一个未被否决的反向分型的中心；反之亦然）。这就是 4.1 第 3 条。它比“末两根是否顺向”多了记忆，比“历史上是否出现过反向分型”多了否决，正好落在甲乙两稿之间。`W8b` 里末根 `[6,16]` 是底 `B@1(0)` 以来的新高，状态为（向上，延伸），滞留消失。

**为什么必须有第 1、2 条。** 尾端分型是链的最后一项，它之所以在链里，是因为它与前一项成笔；它之后的新笔还没有成立。如果后续 K 线突破了尾端自身的极值，按 `077:42`「一个底不经过一个顶后就有一个更低的底，这是最典型的笔没完成的情况。」以它为终点的那一笔并没有完成，走势仍在那一笔当中。`108:18`「跌破分型最低点意味着底部构成失败」说的是同一件事。此时方向应当是前一笔的方向。

而 `parsePens` 在这个时刻不会更新尾端：突破尾端的那根 K 线还没有形成新的分型，要等它之后出现一根反向 K 线。在此之前，链的末项仍是那个已被突破的分型。

```lean
def penOnlineState (r : PenRule) (bars : List (MergedBar P))
    (tie : PenTiePolicy := .preferEarlier) : Option PenOnlineState :=
  match (penPivots r bars tie).getLast? with
  | none => none
  | some f =>
    let ahead := if f.kind = .bottom then Dir.up else Dir.down
    let back := ahead.flip
    let after := bars.drop (f.center + 1)
    let beyond := fun (d : Dir) (p : P) (b : MergedBar P) =>
      if d = .up then decide (p < b.range.hi) else decide (b.range.lo < p)
    let tip := fun (d : Dir) (b : MergedBar P) => if d = .up then b.range.hi else b.range.lo
    let d := if after.any (beyond back f.extreme) then back else ahead
    match after.reverse with
    | [] => some ⟨d, .extending⟩
    | last :: earlierRev =>
      some ⟨d, if earlierRev.all (fun b => beyond d (tip d b) last) then .extending else .forming⟩
```

`after` 为空的分支在合法输入上到不了（尾端分型的右邻必在其中），写出来只是为了让函数全定义。草案未编译。核验：这段逻辑的 Python 等价物与 4.1 的判据在 143,490 例乘两种策略上逐点相等（P7），`OrderDual` 对称（P10），`none` 当且仅当局部分型为空（P8）。

## 五、`U-3`：`klineOverlapBase`（见证 `W15`）

### 5.1 裁定

**`U-3a`**：最低级别 K 线重叠基底在切段之前**先经 M10 的 `klineNormalize`**，开头策略用调用者传入的同一个 `InitIncludePolicy`。

**`U-3b`**：单端相等的包含对**按分叉 4 作无方向吸收**，不作定向推进。先做包含处理之后这一条自动成立：`W15` 的三根 K 线合成一根，输出零段。

**附带裁定**：辅助定义 `rangeStep` 必须改成两端都严格。它现在保留着“一端相等、另一端移动即定向”的分支，与分叉 4 相反。

### 5.2 论证

- **硬证据**：`062:28`、`065:20`、`065:24`、`054:24`、`017:40`、`018:58`、`084:52`、`084:54`、`101:58`、`053:22`、`064:14`。
- **背景旁证**：无。

**（一）原文的两处留白。** `017:40`「定义为至少三个该级别单位K线重叠部分」与 `018:58`「三根以上1分钟K线的来回重叠震荡后回头」都早于第 62 课的包含处理，没有说单位 K 线要不要先处理。`084:52`、`084:54`、`101:58` 说递归的起始程序可以另行设计，条件是分解唯一。所以这里是主线的设计决定，标准只有一个：同一份 K 线，在本包里不能有两种判法。

**（二）不先处理就会出现两种判法。** 分叉 4 已锁定：一端相等即算包含（`054:24` 是它在端点相等上的参考）。M10 对包含对的处理是合并，不产生方向；方向只来自非包含的相邻对（`065:24`）。若 M14 的 K 线基底直接在原始区间上判向，同一对 `[10,20]`、`[10,25]` 在 M10 里是包含、不定向，在 M14 里却是向上推进。这是同一个判定在同一个包里有两个答案。

后果不止于一对。有限例 `W15x`（5 根）：

`[[10,20], [10,18], [10,19], [10,17], [10,18]]`

五根 K 线低点全在 10，相邻每一对都是包含。经 `klineNormalize`，向上策略合成 `[10,20]` 一根，向下策略合成 `[10,17]` 一根，输出零段，也没有任何分型或笔。直接在原始区间上判向则得到四段：下、上、下、上。连续三段有公共区间，按三段重叠即成中枢的口径，这就是一个最低级别中枢。一个被 M10 判为没有结构的图形，在 M14 里凭空生出一个中枢。

**（三）先处理有原文依据，且唯一确定。** `062:28`「经过这样的处理，所有K线图都可以处理成没有包含关系的图形。」包含处理是对任何 K 线图都可施行的预处理；`065:20` 给出顺序原则，结果唯一。在规范形上相邻两根必为严格上升或严格下降，按涨跌切段没有任何歧义。

**（四）与其余三种基底的关系。** `segmentBase`、`fractalDirectBase` 都以 `klineNormalize policy` 起头。K 线基底用同一个入口、同一个策略参数，三者对同一份输入看到的是同一个规范形。分笔成交基底（`053:22`、`064:14`）的输入是单点区间，两个单点互相包含当且仅当相等，不需要包含处理，`rangeStep` 改严格后对它没有影响。

先处理之后，K 线基底与分型直连基底的关系可以写成一条命题：在规范形上，K 线基底的段数等于局部分型数加一（规范形至少两根时）；中间各段的区间等于相邻两个局部分型极值所夹的区间，与分型直连基底的对应段相同。两者的区别是 K 线基底多出首尾两个不以分型为界的残段，且来源跨度按合并 K 线的原始跨度记。这不构成重复：`018:58` 的来回重叠本来就是 K 线涨跌的转折，转折处就是分型。
